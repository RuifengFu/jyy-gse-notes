## 1. AI 让作业与简历同质化，应对之道是学会驾驭 AI

<small>▶ [00:00](https://www.bilibili.com/video/BV1pb8o6yE8f?t=0)–07:22　·　开场　·　话题：从简历焦虑到课程定位</small>

- **计算机的每次变革都把昂贵的能力变成日用品**　讲者列出 PC、互联网、移动互联网和 2022 年的 ChatGPT。他认为现在站在新的交叉路口。
    - **前三次变革让能力走进日常生活。**
        - 1975 年出现第一台 PC，Altair 8800（字幕原文：泰尔8800，待确认）。
        - 互联网连接了所有人。讲者小学快毕业时用 ICQ 随机加海外网友。对方是英语母语者，发来一长串英文，讲者当时只会 hello 和 Good morning。
        - 腾讯的山寨版当时叫 OICQ，后来改名 QQ。
        - 移动互联网一夜之间让所有菜场摊贩都有支付宝和微信两个二维码。
    - **自嘲** 幻灯片上 Altair 的配图是 AI 生成的，模型也不是很强：「你们可以看出有非常明显的 AI 味」
    - **自嘲** 讲者回忆当年用 ICQ 的英语水平：「因为那个时候可能我们刚学一点点英语只会 hello、Good morning」
    - 2022 年的 ChatGPT 是人类历史上增长最快的产品。
    - 讲者认为上课方式和学习内容都需要重新思考，因此决定开设 Vibe Coding 课程。
- **AI 已经替学生做完作业，只有学生没被训练**　老师用豆包出题，学生用豆包做作业。整个过程里只有学生没有受到训练。
    - 「AI 替我上大学」这个说法，讲者认为很对。
    - **吐槽** 讲者描述这个过程：「老师用豆包出题大家用豆包做作业，然后在这个整个的闭环过程当中只有学生没有受到训练」
    - **以前的操作系统作业折磨学生，学生在痛苦中提升，现在一句话就能交差。**
        - 学生把作业链接丢给 Codex，连复制粘贴都不需要。
        - 学生甚至不用给链接，只要说出课程和实验编号。
        - **吐槽** 讲者说以前的操作系统作业：「大家在痛苦的折磨中获得提升」
    - **吐槽** 讲者模仿学生让 AI 写操作系统实验：「那个蒋老师的操作系统课第八个实验能不能去帮我实现啊，好，这就结束了」
    - 该不该学编程，讲者的答案是既应该也不应该。有些能力仍然需要，但怎么学，讲者也不知道。
    - **学生有两种焦虑，都源于学到的东西 AI 也会。**
        - 第一种：AI 帮我上完大学，每门课开卷都全答对，出来却什么都没学会，第一个被 AI 取代。
        - 第二种：一直听老师话、认真听课做作业的学生，毕业时发现学会的东西 AI 都会做。
        - **吐槽** 讲者描述这类学生毕业时的感受：「做完了以后你发现 4 年毕业的时候你被大学骗了」
- **AI 写出的简历千篇一律，申请者之间无法区分**　讲者收到无数份同类简历。没有额外信息的简历在他眼里是零分。
    - 同学们现在最切实的痛苦是保研。大家海投简历，讲者也收到很多，觉得很糟糕。
    - **一份由 AI 处理的示例简历，讲者给零分。**
        - 展示全程由 AI 完成。讲者只说明有一份简历，要上课展示，需要去掉个人信息。
        - AI 把个人信息替换成 Unicode 方块字符。
        - **吐槽** 讲者反讽处理后的简历：「就这样的一份简历，就非常完美的简历」
        - 简历上有一篇 CCF 期刊列表的论文，状态是 accepted。
        - 讲者提到，大家常说论文在投就等于不存在，因为别人看不到。
        - 简历没有 GitHub 链接，没有个人主页，也没有 preprint，没有额外信息。
    - 讲者说同学们的简历多多少少也是这个样子。
    - 所有人都有一大堆实习、奖项和论文，讲者无法把申请者和竞争者区分开。
    - **吐槽** 讲者模仿申请者的千篇一律：「所有人都是我有一大堆实习一大堆奖项一大堆论文」
    - 讲者提出的问题：既然这样的简历是零分，同学们要用什么向未来的导师展示自己。
    - 一篇发表论文对讲者可能是加分项，对很多其他人可能不是。
- **课程用 Vibe Coding 的快乐缓解焦虑，并教软件工程**　讲者在 Vibe Coding 中获得快乐，希望带大家还原这种快乐。
    - 同学们在快乐中能理解软件工程是怎么工作的，能做有趣的东西，也能让简历更好看。
    - 课程题目是「生成式软件工程」，本质上是一门软件工程课。具体做法见第 2 节。
- **顺带：开课前的现场操作和听众背景**
    - 讲者在 Neovim 里按 F，打开了浏览器，随后正式开课。
    - 讲者说在座是计算机专业的同学，从入学起就在听计算机发展史。

> 原话：「但这个简历对我来说是一个零分的简历」

## 2. 课程以案例为主，讲义即代码，考核看你做出了什么

<small>▶ [07:22](https://www.bilibili.com/video/BV1pb8o6yE8f?t=442)–20:24　·　转向　·　话题：课程做法与考核约定</small>

- **课程以案例为主、组织松散，听课型同学可以不到课。** 讲者认为讲义与录像比现场听课更高效，想挑战讲者的同学来线下。
    - 想讨论或挑战讲者的同学可以来线下。听课型同学，讲者建议既不到课也不看直播（理由见下文的讲义流程）。
    - **玩笑** 讲者说明课程政策时：「我希望重新找回同学们心中在大学的时候那种上课耽误学习的感觉」。
    - 讲者推荐同学在课上实践，后面会带着做实践案例。目的是让同学知道，AI 时代的学习和工作方式变了，要尽快适应。
- **讲者用 Markdown 讲义当唯一源头，AI 生成幻灯片，课后再用录像重新切片。** 讲者按 everything is code 的思路，把一门课当程序来维护。
    - **上课前：讲义约束 AI，幻灯片由 GPT-5.6 加工**
        - 左边的 Markdown 是课前写好的讲义，写明什么时间讲什么、举什么例子，用来约束 AI 做什么。
        - 按 F5 播放的幻灯片与 Markdown 不同。紫色部分是 GPT-5.6 添油加醋加上去的，所有图片也是生成的。
        - 添油加醋靠一个 skill（字幕原文：mix lights，待确认）。它生成 3 个子 agent，各有不同性格，在隔离的上下文里工作，主 agent 最后汇总。思路类似讲者的 AI 耿同学。
        - 讲者把这叫作用算力换智力：付出更多算力，得到更多智力。
        - 讲者换了几版提示词，每版重新生成一次。再让另一个模型盲评哪版幻灯片质量高，最终选了质量较高的一版。
        - 流程上 Markdown 是 source of truth。选中的片段由 agent 扩写成 Markdown 幻灯片，再在浏览器里渲染。
    - **玩笑** 讲者谈怎样帮学生学得更高效时：「我希望的是探索一条能够真正杀死大学所有人的路径」。
    - **上课：是一场按剧本的表演**
        - 讲者把自己当演员，按预先写好的剧本演出，调动大家的情绪，同时和大家交流。
            - **玩笑** 讲者比喻上课：「上课是一种表演嘛，比如说我是个演员，要调动大家的情绪」。
        - 演完后要 review。即兴不完美，某个例子可能不恰当，换一个案例也许更让人感同身受。
    - **课后：录像切片后回到讲义，让讲义越改越丰富**
        - 讲者录了像，把录像切成片段，回到代码上把讲义改得更丰富。
        - 桌子、椅子、电脑都可以用 CAD 这样的代码生成（见第 6 节）。
        - 讲者想把要点、逻辑、第一节怎么上，整理成一个程序。讲者以后不维护了，别人可以接手。
        - 例子：讲者会把 B 站的操作系统课录像整理成切片。切片由全世界的人维护，各人定制自己想要的操作系统课。
        - 讲者认为这能把大学教课的方式推到顶峰，是可能实现的路线。本课只做较轻的尝试，欢迎反馈。
        - **玩笑** 讲者说这条路线的效果：「这不就把所有大学教课的方式给颠覆了嘛」。
    - **玩笑** 讲者说课后重新整理录像时：「我不就实现了数字永生了吗对吧，我就实现了一个课程的数字永生」。
- **课程禁止古法编程，学生要在课上学会用 AI 干活。** 讲者相信学生都是古法编程好手，但认为体系总有一天会变。
    - 学生要考试，要保研机试，被关进小黑屋就写代码。
    - **吐槽** 讲者说学生看过自己以前出的题：「你们看过我以前出的题然后就吓尿了对吧，赶快再去 LeetCode 上刷一下」。
    - **吐槽** 讲者说到保研机试前的集训：「就把你们一关小黑屋一关，对吧」。
    - 讲者认为体系自上而下传导不会快，改变很难。他想先撕开一个小口子。
- **token 自费，课上用便宜的 DeepSeek V4 Flash 就够** 讲者本想拉 token 赞助，看到选课人数后放弃。
    - **自嘲** 讲者说不想为赞助去求人：「我也没有必要再去跟他们拉着脸去要好多好多的 token，也比较麻烦」。
    - 讲者个人观点：手上没有付费 token 的同学应该立即退学。硅谷有人拼命烧 token，同学没有必要。
    - **吐槽** 讲者说没有付费 token 的同学：「如果你们手上没有 token、没有付费 token 的同学应该立即退学」。
    - 课上演示只有幻灯片生成用更聪明的 GPT-5.6，其余全用 DeepSeek V4 Flash。它足够便宜，也有一定智能。
    - 讲者说计算机系学生都是夜猫子，喜欢在夜里工作。
    - **玩笑** 讲者说同学的作息：「你们都是夜猫子，当然是 computer science 的学生，你们喜欢在夜里工作」。
    - 讲者建议同学在夜里用 DeepSeek，因为夜里便宜。建议每人充 100 元，讲者觉得可以接受（字幕：迪士个，可能指 DeepSeek，待确认）。
    - **玩笑** 讲者建议错开 DeepSeek 的时段，说白天上课、晚上做作业正好对上（字幕原文：梁文峰，梗待确认）：「在白天你们要上课，正好是梁文峰时间是吧」。
    - 有 token 困难的同学可以联系讲者，讲者帮忙想办法。
- **考核只分通过/不通过，真正的成绩是简历上的作品。** 模型不同质量不同，无法统一评分，讲者认为分数已不重要。
    - 讲者申请课程时填的考核方式就是通过/不通过。教务反馈这是专业选修课，通常只有《形势与政策》这类课这样评。

## 3. 大模型只是概率分布，加上循环与工具就成了能自主干活的 Agent

<small>▶ [20:24](https://www.bilibili.com/video/BV1pb8o6yE8f?t=1224)–29:56　·　转向　·　话题：大模型到 Agent 的演进</small>

- **大模型本质是概率分布，使用者不必懂内部。** 它和概率统计课上的抛硬币题没有区别，课程只站在使用者的视角。
    - **玩笑** 讲者拿概率课的题目类比：「我抛了六次硬币加起来是40，然后你问第一次抛出一的概率是多少」
    - **一本书加一句话，模型就接着往下写。**
        - 输入是一段很长的文本，也可以是图像，例如一本书。
        - 在书后面写「能不能帮我总结一下这本书」，然后输入结束。
        - 模型不断预测下一个 token 的概率，每次输出一个字符。token 是模型输出的最小单位。
    - 模型很大，见过世界上所有东西，训练很难，所以 frontier lab 很强。
    - 打开 DeepSeek 网页或 API，问「什么是大语言模型」，就是在体验它，不需要任何大模型知识。
- **从 GPT-4 到 GPT-5.6，同样的需求从反复调 prompt 变成一句话** 讲者用「给孩子打比方」和「批量生成」两个任务对比。
    - 2023 年 GPT-4 幻觉严重，当时靠 prompt engineering，要求用朴素语言打比方，帮五岁孩子理解扫描电子显微镜。
    - **自嘲** 讲者回忆第一次败给大模型：「我第一次被大模型按在地上打，是给我五岁的孩子」
    - **模型打的比方让讲者震惊，因为它既有知识又准确。**
        - 讲者给孩子讲故事时讲到扫描电子显微镜，自己讲不下去。
        - 比方：闭眼向看不见的山扔石头，有的方向穿过去，有的方向弹回来，弹回来能听到声音。
        - 根据哪里穿过、哪里弹回，推测山的形状，像 ray tracing。
        - 讲者事后查了资料，比方是对的。孩子不可能百分之百听懂。
        - 课上展示的比方由 GPT-5.6 生成（字幕不清，待确认）。它有 reasoning，解释更严谨。
    - GPT-4 时代，一个 prompt 能给 LLVM 找到 150 个（字幕原文：GCLVM，150 个对应的对象待确认）。今天是一句话的事，不需要为模型做特别调整。
- **模型加上循环和工具就成了 Agent，能自主干活。** 模型输出越来越长、上下文越来越长，出现了推理模型和 ReAct 式 Agent。
    - **ReAct 式 Agent 的原理：模型请求调用工具，结果送回循环。**
        - 模型可以输出一个特殊 token，请求调用一个 bash 程序。
        - bash 程序的运行结果重新送回 Agent 的 loop。
        - Agent 因此可以自主运行，不断尝试，直到完成复杂任务。
        - 出错以后，Agent 会去试别的方法，最后把任务做完。
    - **讲者把终端配置整个交给了 Agent，只写了一个 prompt。**
        - prompt 大意是：把命令行终端和系统配置成现代、好用的样子。
        - 窗口管理器（字幕原文：space，待确认）为课堂展示做了优化，对比度高，去掉了顶栏。
        - 大家都习惯用 top 看系统里的进程。讲者的 top 换成了更好看的版本。

## 6. 懂计算机的人知道什么该交给模型、什么该写成确定性代码

<small>▶ [64:52](https://www.bilibili.com/video/BV1pb8o6yE8f?t=3892)–74:47　·　但是　·　话题：计算机人的边界与 Excel 偷数据</small>

- **计算机人知道哪些交给模型，哪些写成代码** 一般人的需求常常失败。计算机人知道什么该以代码复用，什么该以 skill 复用。
    - 一般人提的需求，agent 可能做不好。一般人也不知道怎样 prompt，才能让 agent 确定性地快速完成。
    - 计算机人知道编程能力的界限，也知道怎样把需求编译成可复用的东西。
    - 只用 agent 做操作系统作业，是小看了它。
    - **吐槽** 讲者对只拿 agent 做作业的人毫不客气：「如果你们只是用 agent、Codex 说的方法把操作系统作业做了，那你们真的是太小看它了」
    - 讲者以改卷统分为例。统分一般交给助教，助教掏出计算器，加完再核一遍。
        - **吐槽** 讲者说这种做法对学生太好，但这条路也走不通：「所以我觉得我对我的学生太好了，这个也不行啊」
- **统分流水线只让模型做识别，加法由脚本完成** 模型会因幻觉算错，脚本不会，所以总分用 eval 脚本算。
    - 讲者今年先用 Vibe Coding 生成脚本并测试，再跑完整流程。
    - **第一阶段：拍照加离线识别。**
        - 办公桌上有一个自上而下的摄像头，对准试卷的固定位置，预先调好。
        - 讲者每按一次回车拍一张照。卷子没摆好，就调整后重拍。
        - 拍完后，脚本离线调用千问识别姓名、学号和每个小分，每张卷子写一行到文本文件。
        - 拍照时双手都不用放下笔。
    - **第二阶段：语音播报加人工核对。**
        - 顺序反过来，仍按回车。左手按回车，右手拿笔。
        - 系统语音播报学号和每个小分，讲者边听边检查。
        - 讲者检查的理由是 OCR 会出错：「我不信任他，我要对我的班上的每一个同学负责」
        - 核对无误后，讲者把脚本算出的总分抄到卷面上。
    - 讲者没有让大模型做加法，所以每个分数他都亲自看过。
    - 分数自动汇总到教务处的 Excel 模板。讲者上传前抽样检查，确认无误再提交。
- **本地模型加脚本的分工，来自对边界的判断** 讲者想降低人和 agent 之间的同步代价。他还想让流程最舒服。
    - 讲者知道本地有 27B 的千问（字幕原文：千万3点八，待确认），也能用 Ollama 跑。
    - 一般人对最好的模型说「140 张卷子改好了，小分已写上，帮我统分」，到不了这样快的收敛方案。
    - 现在人和 AI 还要共建。讲者赌将来 AI 强到能感知他的一切，帮他制定完美的方案。
- **everything is code，所以能生成的东西远不止文字** 视频、论文、3D 打印物都可以由代码生成。
    - 讲者说，想象力限制你能做什么。
    - 一般人用 agent 可以学习、看书、做总结，也能实现信息处理的循环。
    - 一般人还能用 computer use 和 browser use，去做日常里的任何操作。
    - 讲者正和一位同学做 WIFI（待确认）项目。用自然语言就能让 3D 打印机打印出东西，这是 Python 代码生成的。
    - 这实现了从 bit 到 atom（字幕原文：从B到ATEMS，待确认）。AI 的能力只会变强，不会变弱。
    - 讲者留下两个问题：这一天什么时候到，以及人该怎么面对。
- **顺带：讲者先说普通人的视角，再转到计算机人的视角**
    - 公众号的消息，和第一手用过的人的感受很不一样。
    - 讲者说这个时代已经来了，需要认真思考这件事。

## 7. AI 擅长完成任务却不会设计，软件在意图到实现的鸿沟上暴毙

<small>▶ [74:47](https://www.bilibili.com/video/BV1pb8o6yE8f?t=4487)–94:47　·　但是　·　话题：软件工程鸿沟与 AI 的失败</small>

- **AI 能做好每个环节，却不会设计，产品照样暴毙** 产品是系统工程。AI 能完成任务，但生成的代码无法维护。
    - **玩笑** 讲者替听众配了一段内心独白，随即转折：「我三观尽毁了，时代的车轮来了，我已经被压在车底下了，不着急」
    - **玩笑** 讲者拿 LLM 之前商学院同学常说的老梗开场：「idea 都有了，就差一个程序员了，我们去挣一个亿吧。ABCD 轮也都有了，就差一个天使投资人了。」
    - 做外卖网站要做前端、后端、交互、运营，任一环节没做好，产品直接暴毙。AI 看过世界上所有的书，每个环节都能做，但组织不好，同样立即暴毙。
    - **教务系统是不可维护代码的典型，加一个校区就要大改**
        - 学校每年花钱请公司维护这份代码，原因是添一个功能就很难。
        - 讲者用 browser use 时 hack 了系统，发现隐藏字段，例如学生所在校区。苏州校区建成前，系统不需要这个字段。
        - 需求设计时没想到学校有校区，数据库里没有这一项。产品经理突然要求两个校区的选课分开，就要改。
        - 现在可以直接告诉 AI 新增校区，它会写代码，但仍然容易失败。
    - **QR 实验：需求写明了，模型仍然误解，或靠硬编码交差**
        - 需求明确：只用 Excel 2019 兼容公式，把任意字符串转成 QR 动画。
        - 讲者要求 AI 做到做完为止，不要中途停下来问，因为它经常做到一半就停。
        - GPT-5.6 想实现对任意字符串都正确的版本，第一秒就被带歪。软件工程的第一步是不扩大范围，先做最简单的东西。AI 容易在小 corner case 上犯错。
        - 讲者说模型看过他完整的 slides，但他没告诉模型自己是怎么做的（字幕不清，待确认）。
        - 第一版是讲者带着 AI 用 Vibe Coding 做的，比较顺利。
        - 受控实验把规格直接交给 GLM-5.3。它先思考 25 分钟，输出超过 32K output token，被 Claude Code 的默认上限截断。
        - 讲者没有监管，它总共跑了 6 小时，结果正确。讲者说 GLM-5.3 的厂商强调它擅长长程任务，这次确实做得好。
        - DeepSeek V4 Pro 晚上放着跑，次日早上发现它已不遵循指令，用了硬编码。
        - 规格要求用 Excel 公式给任意字符串做 Base64 编码。它却用 Python 算好 Base64，贴进公式框。字符串一改，Base64 不会跟着改。
        - 讲者骂了它，它回应这是设计缺陷，要重新想（字幕不清，待确认）。
        - **吐槽** 讲者讲起骂模型的经过：「然后我就骂他了，我骂完以后，他那个 channel 少女就说……」
    - 两个模型都完成了任务，生成的系统却无法继续维护。死法和教务系统完全一样：知道需求，实现需求，然后陷入维护泥潭。模型没有先想软件架构。
    - 讲者提到一个夸张的说法：做一个能活 100 年的软件。50 年里操作系统和用户界面都变了很多。不知道有没有软件能活 100 年，GPT-5.6 也不知道。要活下来需要好的架构。
- **先让 AI 设计中间语言，再实现，代码才可维护** 讲者让 GLM-5.3 先设计中间语言，分块验证。一次生成就得到干净的正确代码。
    - 讲者先出了一道小测验：如果由你们实现这个 QR 动画，会怎么写 prompt。他自己只用少量 prompt，GLM-5.3 在 200K 上下文内就完成第一个正确版本。当时他刚升级到 GLM-5.3，想测试它的能力。
    - **做法有 4 步，核心是先搭编译器式的基础设施**
        - 让模型设计一组 Python 类，像编译器一样，组成一个符号系统，包括 XOR 和 concat。
        - 每个符号既能翻译成 Python 直接执行，也能翻译成 Excel 公式。这就是中间语言，对 Python 和 Excel 都友好。
        - 分开验证：编码算得对不对，二维码每个像素算得对不对，每个到 Excel 的翻译对不对。
        - 验证完成后一次生成，代码直接正确，干净不长，维护性远好于硬编码版本。
    - **硬编码版本一改就崩，说明可维护性差**
        - 讲者现场翻看了 GLM-5.3 和 DeepSeek 两份代码，路线不同，思路一样，都是大量硬编码。
        - 讲者让两份硬编码代码把工作区移到另一个位置。
        - 每份都要修约 2 小时，agent 不停出错。
        - 原因是所有东西都硬编码，改错一点，验证就通不过。
        - 讲者认为 agent 可能最终修得完，但这是软件工程问题。
    - 所以今天仍需要生成式软件工程。讲者把自己作为软工人的所学用在这门课上。他认为 AI 应该也懂这些，但可能因为后训练，AI 上手解决问题的欲望太强，效果不够好。
- **软工的难点是意图、规格、实现之间的鸿沟，模型靠猜来补** 后训练的奖励让模型急着完成任务。模型不去澄清需求，人则是先学实现再学软工。
    - **用 AI 解决问题时有 3 个空间**
        - 意图空间：你脑子里想的事。例如老板说「做一个国民级应用」或「做个小程序挣一个亿」。有人想做外卖，有人想做 AI 读论文（AI 耿同学）。
        - 规格空间：每个意图有很多种规格。规格包括程序有什么功能，满足什么要求，有几个界面，每个界面做什么。
        - 实现空间：同一份规格仍有大量不同的实现，架构和实现方式的选择在这里。
    - **每一层的选择都截然不同，鸿沟就在层与层之间**
        - QR 实验：意图是造一个能偷出二维码数据的 Excel，规格是那句需求。不同架构和实现方式带来巨大差别。
        - 教务系统：校长只有一句话，要做学校里所有同学相关事情的信息化，公司说能搞定。
        - 提需求的人可能是甲方或老板，没有任何计算机经验。
        - 之后要选界面怎么呈现，数据库 schema 怎么定，分几张表，每表几列，用 key-value 还是关系型数据库。
        - **吐槽** 讲者说到界面怎么呈现，顺口点评教务系统：「我觉得这个界面设计很糟糕」
    - 讲者放出软工早年的一张梗图。图中客户、项目负责人、分析员、宣传人员各自理解不同，最后造出来的和客户要的不同。根因是空间之间的鸿沟。软工和生成式软件工程都要补上这些鸿沟。
    - 今天模型用猜来补鸿沟。后训练时，任务做完、测试通过就得奖励，模型形成倾向：立即上手，尽快完成。好处是能做的简单任务越来越多，但和人解决问题的方式不同。
        - **玩笑** 讲者替模型配内心独白：「你既然说了这句话，那我猜应该是这个吧，我就去实现」
        - **玩笑** 讲者解释模型为什么抄近路，顺势自嘲：「我们每个人都是 reward hacker，是吧」
    - 人的路径不同。计算机学生大一先学 C 语言，学的是实现空间，熟练后再上软工课，一点点补全。AI 时代既要阻止 AI 乱猜，又要发挥它从 A 到 B 的能力。讲者说这是本学期要讨论的问题。
- **项目一旦开始失败，加投入只会更糟。所以软工是多学科的方法论** 《人月神话》说失败的项目加人只会更失败。AI 加 token 也一样。
    - **焦油坑比喻对人和 AI 都成立**
        - 《人月神话》的比喻：大型动物陷入焦油坑就难逃脱，濒死的动物又引来掠食者，掠食者也出不去。
        - 经典论断：软件产品已开始失败，再加更多人只会更失败。
        - AI 已开始产生 slop 时，投入更多 token 也只会更失败。AI 在失败的东西上一点点往上堆，直到付不起 token 为止。
        - 教务系统每年都在增加功能，讲者认为就是这样。
    - **吐槽** 讲者说教务系统一年年加功能，学校花的是纳税人的钱，随即转口：「学校又花了很多这个纳税人的钱，就这个，呃，Anyway，这也许不是坏事，因为它促进了经济的发展，对吧」
    - **软工研究的是鸿沟存在时怎么做成大事**
        - 教务系统比 QR 实验大，是能让公司挣几 100 万、几 1000 万的产业级产品。国民级产品更大。
        - 软工方法论来自投入 billions of dollars 的教训。管理者带着很多聪明人，也曾陷进去。
        - 南大做程序分析和测试的老师，在已有代码时自动生成更多测试用例或代码审查。代码不满足规格或可能不满足意图时，发出 warning。
        - 讲者提醒，进课题组做研究时容易忘了这个 big picture。
    - **软工有技术、人类学、社会学、管理学四个部分**
        - 在生成式软件工程里，这些人变成了 AI。
            - **玩笑** 讲者对比 AI 和真人团队：「你管一堆不会和你抬杠、只会 you are absolutely right 的……」
        - 人不听话怎么办，如何控制团队风险，人离职、跳槽到竞争对手怎么办，都是软工要研究的。
        - 软工研究领域包括 7 个：AI for SE、SE for AI、架构设计、可靠性、演化、human social aspects、需求。
        - 「演化」指这个软件能不能长期生存下去。
    - 需求环节特别重要，因为越早，鸿沟被放大得越多，像一个杠杆。这里微小的改动，会在后面变成巨大的变化。大型软件系统多半在这里出错，最终整体崩盘。

> 原话：「就是软件工程里面最经典的死法，上来我知道需求了，我把这个需求实现了就好了，直接就陷入了维护的泥潭。」

## 8. 考试训练出的做题家不如 AI，工程品位也许是人最后的价值

<small>▶ [94:47](https://www.bilibili.com/video/BV1pb8o6yE8f?t=5687)–100:02　·　进一步　·　话题：AI 还缺品位与课程展望</small>

    - AI 数据更多，反馈信号更明确，所以做得比你好。
    - 没有好奇心，不想知道产品怎么开发，就没有自驱力去训练长程问题。结果是长程问题也不如 AI。
- **模型还没学会设计，仍是做题家**。强化学习对真实长程信号的奖励做得不够好，模型更多在机械完成任务。
    - GPT、Claude、GLM、DeepSeek 面对 Excel 问题（见第 6 节），都不会先设计中间语言（DSL）。它们有足够智能给出干净、可维护的方案。
    - **吐槽** 讲者说模型的第一反应和学生一样：「他已经被训练成做题家了」
    - 软件工程失败的定义没变：意图到规格再到实现的翻译出错（见第 7 节）。
        - 一种失败是产出的东西不是我要的，即意图与规格对不上。
        - 另一种失败是实现不满足规格，比如正确性或性能不达标。
    - 软件工程课常被抱怨像文科。把技术映射回去，它是管理学，里面仍有真实有趣的科学。
        - **吐槽** 讲者认同软件工程课像文科：「这就是一个文科嘛，就是一个管理学，这是一本管理学的书」
- **AI 可能学会工程品位，讲者因此有危机感**。模型会数学和细碎的编程逻辑，也见过好设计，可能从记忆里调出来。
    - 常说 AI 最缺品位，需要训练好的工程品位。讲者认为既然能做做题家，就可能有品位。
    - 讲者有些 SKILL 已在朝这个方向做。
    - **自嘲** 讲者担心课程三个月内就过时：「我在上着上着这门课，所有东西就不存在了」
    - 思考题：怎么设计 AI 主导 QR 开发的研究（字幕不清，待确认）。GPT-5.6 的答案很糟糕，两个设计都会失败。AI 学不会品位会怎样，讲者不知道。
        - **吐槽** 讲者评价 GPT-5.6 给的设计：「答案非常糟糕，就是这两个设计都是一定会失败」
        - 讲者说，我们做一切事情的方式可能都会发生变化。
- **导师为什么招你而不买 Claude Max，是学完要回答的问题**。古法编程已死，AI 单任务无人能敌，软件工程暂时没死。
    - 讲者说这门课只是一次探讨，他也不敢说自己做得对。
    - GPT-5.6 的回答：找值得解决的问题，把未知拆成便宜的实验，用证据让坏方向及时停下，对长期结果负责。
    - 讲者认为回答不错，但 GPT-5.6 自己做不到。
        - **玩笑** 讲者夸完回答又补一刀：「这个问题上 GPT5.6 回答的还挺好的，虽然他做不到」
    - 课程内容会重新切片整理，不会立即发布。讲者还会发剪辑过的「生肉版」，可与精修版对比。
