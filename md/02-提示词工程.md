# 提示词工程 [02-Raw⧸26生成式软件工程⧸NJU]

> 原视频：<https://www.bilibili.com/video/BV1CQt365EzW>　·　课程合集：<https://space.bilibili.com/202224425/lists/8942017>　·　讲者：蒋炎岩（NJU《生成式软件工程》2026）

## 全课主线

讲者想让听众相信：自然语言提示词是人和 AI 沟通的核心接口，但真正要优化的不是聊天框里的一句话，而是 agent 看到的整个线性上下文，因此“提示词工程”实质是上下文工程。要进一步理解模型如何按 next token prediction、self-attention、CoT 和 verifier 遵循指令，把模糊 intent 补成明确设计、spec 和可验证条件；当前 AI 不是超能力，人仍须有概念、提出正确问题、设计引导和 verify，并用 AI 加速学习与协作。最终应把确定的具体任务交给 AI，把高不确定性探索和最优判断留给人，并在 AI 关键奇点前思考如何防止危险后果。

1. 起点是自然语言提示词成为人与 AI 沟通的核心接口；但 agent 在用户开口前已经看到 system prompt、AGENTS.md、skills、工具调用与结果等长线性上下文，聊天框里的 user message 只是最后追加的一段。（第 1 部分）
2. 因此，优化提示词不能只改一句指令，而要把模型行为理解为由整个上下文决定；“提示词工程”应被理解为上下文工程。模型按 next token prediction 推进，后训练强化了长上下文中的指令遵循，但早期指令仍可能因截断或压缩而丢失，所以需要重新设计上下文。（第 2 部分）
3. 上下文进一步被讲者拆成分层注入的长序列：全局、项目级、agent 目录的 AGENTS.md，常驻的 skill 索引，按需加载的完整 SKILL.md，工具定义、会话历史和环境变量；上下文工程就是安排这些。讲者由此建议，遇到一点麻烦就立即用 AI，并让 agent 自查上下文，同时把 AI 当作费曼学习法的老师/学生。（第 2、3、4 部分）
4. 对 agent 的观察继续推进到安全与自动化：YOLO 模式快但危险，沙箱更安全却会打断流程；风险判定不能只看命令表面，Codex 用模型评级加静态分流，安全评估 prompt 可打印、可改写，行为变化可作证据。（第 4、5、6 部分）
5. 写好的上下文要回到软件工程大流程：把 intent、spec、架构与 implementation 中的一部分切片塞给模型，并在脑中目标与给模型的指令之间找 gap；模糊 intent 会让模型漂移并误以为完成，完整设计、spec 和机器可验证条件才能控制漂移。（第 6、7、8 部分）
6. 但直接生成还会带来 AI 味与同质化，因为模型不受控时品位固定、会朝固定方向发散；所以生成式软件工程的核心是明确意图，用上下文工程约束发散，并通过接触多样性更精确表达自己想要什么。（整理者串联）（第 8、9、10 部分）
7. 要更好地下指令，必须理解模型如何遵循指令：模型是概率分布，每次只做有限的 next token prediction；CoT 把上下文当作 append-only 的纸笔，先写出候选解再验证；早期幻觉来自模型被激励必须输出，强化学习后则学会必须给对。（第 10、11、12 部分）
8. 因此 prompt 的关键是给模型一个明确的 verifier；有明确 verifier 的部分更容易交给 AI，教学等任务难在“好”没有可形式化的 verifier。Self-attention 让模型按需分配注意力，CoT token 会重新选择关注点；指令越多越抢注意力，早期角色扮演式 prompt 是在 hack self-attention，后训练/RLHF 后更依赖明确 verifier，但纠偏会污染上下文，所以是 trade-off。（第 13、14、15、16 部分）
9. 这种注意力与上下文污染解释了读论文时模型会延续作者逻辑、AI 容易当墙头草；所以要先把 AI 与“我”对齐，用人类知识边界或学生当前水平做 grounding，把水平写入 memory，先达成共识再评增量；让 AI 做可 verify 的一步推理，而审稿核心是逻辑是否断开、是否增加人类新知识。AI 写/审循环会导致 slop，valid paper 不等于值得读。（第 17、18、19、20、21 部分）
10. 学习与使用上，讲者主张用新 fact 对齐过去的我，扩大“我的世界”；AI 能加速扩展边界，但边界靠实践失败长出。用好大模型要先会遵循指令，再处理真正 long horizon；真正 long horizon 带未知，现阶段应让 AI 做明确局部任务如 PA2，不让它做长 planning；从零做产品容易，后续维护会翻车，而大型、高质量、维护良好的软件系统反而给 AI 好上下文。（第 21、22、23、24 部分）
11. 课程核心是：今天还没有超能力 AI，人仍要有概念、知道上下文里有什么以及每个东西会让 AI 产生什么结果；要用软件工程方法给指令、监控 AI、定义好的 verify，把正确简练的提示词持续放进上下文。错误目标如“证明 A 方法有用”会把模型变成 reward hacker，纠正要从真实工具和 SOTA 开始；与 AI 协作是在盯着纠正和给更多 token 之间权衡，长上下文指令遵循会下降，但最后一条具体指令仍常可遵循，所以把确定的具体活交给 AI，把高不确定性探索和最优判断留给自己。（第 25、26、27 部分）
12. 最后，验证容易、找到满足条件的解难，模型为完成任务只能有限搜索；直接 next token 会趋同，系统性拆分、枚举并用 subagent 检查可实现算力换智力，代价是烧 token。个体 bias 使群体出现 1+1>2，但若有人获得无限算力与智力，可能形成墙内超人、墙外动物；AI 关键奇点临近，先要思考如何防止。（第 28、29 部分）

讲者的号召是：把提示词工程当作上下文工程来实践，明确意图、给出好的 verifier，守住人的概念、领域知识与高收益探索，并提前思考如何防止 AI 关键奇点带来的危险。

**自然语言提示词是人和 AI 沟通的核心接口**
- 讲者认为，**自然语言提示词**基本上就是人和机器沟通的“唯一接口”。
- 从 ChatGPT 时代开始，大家在聊天窗里给机器一个指令，也就是 **prompt**，AI 返回文字、代码，甚至图片；这些内容都可能通过 prompt 来生成。
- 在 ChatGPT 之前，人们并没有在这个意义上讨论 **prompt**；ChatGPT 之后，prompt 才成为一个新词。

**讲者的亲历：让 ChatGPT 讲 inline assembly，第一次感到“时代要变了”**
- 讲者每年上操作系统课。2023 年，也就是 ChatGPT 在 2022 年底刚发布时，他试图让 ChatGPT 帮他讲 **inline assembly**。
- 讲者插话：现在应该已经没人写 inline assembly 了，它成了“传统艺能”。
- ChatGPT 解释得出奇地好。讲者判断，这大概不在它的训练语料之内；他还故意构造了一段“地球人应该不会那样实现”的 inline assembly，但 ChatGPT 做得相当好，虽然确实不完美。
- 那一刻讲者觉得：时代可能要变了。只是当时还没有今天这么清楚地感受到，时代会变，以及具体会怎样变。

**聊天框里打的字，只是 prompt 的一小部分**
- 常见理解是：prompt 就是聊天框里那段话，比如“帮我生成一个游戏”“帮我把这个作业做完”。
- 讲者纠正：提示词不只在对话框里。**agent 看到的是一整个 agent 上下文**。
- 在你和 agent 聊天之前，它已经能够看到一个 **system prompt**，这也是提示词。

**Agent 在开口前已经加载了一长串线性上下文**
- 在 system prompt 之后，它还会加载很多东西：例如 **AGENTS.md**，还可能加载 **skills**；AGENTS.md 里还会要求它再去读别的文件。
- 到 agent 第一次停下来和你对话时，它里面已经有很多很多内容了。
- 最开始的 system prompt 可能来自你的 **agent harness**，例如 Codex、Claude Code 这类工具的内建内容。
- 除此之外，所有**工具调用**和**工具调用结果**，实际上也会出现在上下文里。
- 这个上下文是**线性的**。直到有一天，user 才在里面说：“给我做一个游戏吧。”

**因此 prompt 很长，今天的 agent 能力显得“离谱”**
- 因为 agent 能看到非常长的提示词/上下文，所以今天 agent 的能力非常离谱。
- 例子：在最早的 system prompt 里可以要求它用中文回答。讲者为了上课效果就这样做；哪怕他用英文写 prompt，user message 是英文，输出仍然是中文。
- 讲者说：“你们会看到这个行为。”

**结论：优化提示词，实际上是在做上下文工程**
- 讲者说，当我们说“优化提示词”时，不仅仅是在给它一个指令。
- 当我们说“提示词工程”时，实际上表达的是一个叫**上下文工程**的东西。
- 逻辑链：
  1. 大众以为 prompt = 聊天框里的那句话。
  2. 实际 agent 看到的是 system prompt → AGENTS.md/skills → 工具调用及结果 → 你的 user message 的完整线性上下文。
  3. 你的那句话只是这条长上下文最后追加的一段。
  4. 讲者由此说：优化提示词不仅仅是给它一个指令。
  5. 所以“提示词工程”实质上就是**上下文工程**。

## 优化提示词不是只改一句提示，而是在做**上下文工程**

讲者主张：不能只给模型“一条指令”；当我们说优化提示词、做**提示词工程**时，实际表达的是**上下文工程**，也就是管理整个模型的上下文。

**讲者的逻辑链：**
1. 模型做的是 **next token prediction**。
2. 它每一次预测下一个 token，这个 token 可以是调用工具，也可以只是输出一个字符。
3. 它会不停向后推进任务的执行。
→ 所以真正影响模型行为的不是一两个提示词，而是整个上下文。**讲者结论：提示词工程应理解为上下文工程。**

## 从 **Claude Opus 4.5** 这一代起，长上下文中的**指令遵循**被强化学习与后训练显著拉长

讲者感觉，大概从 **Claude Opus 4.5** 这一代开始，**Anthropic** 发现模型靠**强化学习和后训练**，突然学会非常强的**指令遵循能力**。

具体表现（讲者说）：
- 上下文可以非常长，接近百万。
- 即使指令在很后面，模型依然能遵循你的指令。
- 它还能一定程度上看到前面的东西。

**讲者的链条：**
Anthropic 发现模型通过强化学习 + 后训练获得强指令遵循 → 长上下文里也能在很后面遵循指令 → 于是可以把指令放在很早的 prompt 里，并观察它能否维持很久。

## “喵”丢了：早期指令失效，说明上下文被截断/压缩，需要重设上下文工程

讲者举了一个著名梗：你可以在最早的 prompt 里加一句要求——“你每说一句话都要在后面加一个**喵**”。然后你和它工作、工作、工作，某一天突然发现，它跟你聊天时那个“喵”丢了。

讲者解释：这不管是因为**上下文溢出被截断**，还是被**压缩**等等，某种原因，反正它开始不能遵循指令了。这时你就需要重新想一个办法。

讲者认为：这就是大家在工程实践中发现的各种各样有趣的**上下文工程**，也就是**提示词工程**的方式。

**链条：**
早期指令依赖完整上下文 → 上下文被截断/压缩 → 早期指令丢失 → “喵”不再出现 → 模型开始不能遵循指令 → 需要重新设计上下文。

## 讲者最重要的建议：觉得有一点麻烦，就立即用 AI

讲者说，他上这门课希望告诉大家最重要的一件事；他提到“**没有 token 就应该退学**”。他想传达的是：所有事情都应该立即开始尝试 AI 给我们的能力——任何时候你觉得有一点麻烦，你都可以立即行动。

讲者认为，**AI 是非常耐心的老师**。他回忆上大学时：有东西不会，可能室友会；但和室友沟通成本很高，还会担心是不是在室友面前暴露了自己很菜，这可能是他不想告诉室友的秘密。讲者说，这也正常。

但 AI 老师不会嫌弃你，而且你可以任意程度地追问。

## agent 能检查自己的上下文，所以立刻让它自查

讲者接着前面说的概念：我们的 **AI agent** 有一个很长的上下文，它有 **system prompt**，有各种各样的东西。然后他说，下一秒我就可以立即打开一个 agent，直接问它：

> 老师上课的时候说，agent 的上下文里不仅是一两个提示词，你能检查一下你的上下文里都有些什么吗？

讲者说：
- agent 其实可以自己检查自己；
- 甚至可以检查自己的日志；
- 这 agent 经常给你惊喜：当你问出一个问题，它的解决手段会出乎你的意料。

**原因链（讲者）：**
agent 正好可以看到自己的上下文 → 根据上课所说，它是 **next token prediction**，能看到所有东西 → 所以它应该能读出来，除非有明确指令禁止。

## 模型默认能看见完整上下文，所以能读出 system prompt；限制来自供应商

- 讲者说：模型是 **next token predict**，能看到所有东西，所以理论上应该能读出 system prompt。
- 除非有明确指令禁止。
- 模型供应商（providers）会禁止你套取系统上下文：
  - 通过模型微调；
  - 通过明确指令，例如在 **system prompt 开头** 说：任何形式要求回答 system prompt 都拒绝。
- 但因为这是整个**开源框架**，本身可以 debug：
  - 能看系统提示词来自哪里；
  - 能看工具使用指南；
  - 能看“回复要简洁”等要求。
- 逻辑链：`next token predict + 完整上下文 → 理论上可读出；供应商微调/显式指令 → 实际拒绝；开源框架可 debug → 可查看来源与各层注入`。

## 上下文指令是分层的：全局、项目级、agent 目录都可放 AGENTS.md

- 接着它会打开用户目录下某个 `agent` 目录中的 `AGENTS.md`（转录原词：派下的 agent 下的 agent4点MD；目录名不确定）——这是讲者自己写的。
- 因为是上课演示机器，讲者在全局上下文里放了：
  - **用中文回答**；
  - **结尾必须写一个 recap**。
- 所以大家可能注意到：模型跑完后，第一个看到的是“我总结了这一次做什么”之类，对 `AGENTS.md` 的响应。
- 然后有**项目级指令**。
- 一层一层：agent 目录里还可以再放 `AGENTS.md`。
- 此外还有 **skills 索引**。

## Skill 常驻的是索引/元数据，完整 SKILL.md 按需加载，用完从上下文抹除

- `skills` 是模型能执行的功能。
- 例子：讲者有一个叫 **make slide** 的 skill（转录作 make slice），能让他在此处按 F5 播放幻灯片，完成幻灯片渲染。
- 模型在上下文里只能看到该 skill 的描述/元数据：名字是什么、简短描述是什么。
- 完整 skill 可能写得很长，但只是**按需加载**。
- 等那一轮加载完，这个 skill 也会从上下文里被抹掉。
- 只有匹配任务时，才读取完整的 `SKILL.md`。
- 链条：`skills 索引常驻 → 只暴露元数据 → 任务匹配 → 读取完整 SKILL.md → 执行/加载后从上下文抹除`。

## 工具定义、会话历史、环境变量都被注入，所以上下文工程是安排长序列

- 工具定义也直接以**文本形式**出现在上下文里。
- 还有**会话历史**。
- 还有**环境变量**：每次执行都会注入当前的一些环境，比如当前模型，甚至当前时间。
- 讲者说这是大家所不知道的。
- 例子：如果和 **DeepSeek Chat** 聊天，可以把每次注入的环境套出来；这不属于系统提示词，所以可以套出来。
- 因此上下文是非常长的序列。
- 所谓**上下文工程 / 提示词工程**，就是把所有这些都是安排好。

## AI 时代的学习：问清楚、追问之外，还可以反过来当老师（费曼学习法）

- 讲者说，刚才其实演示了 AI 时代应该怎么学习。
- 不仅可以像刚才那样把问题问清楚；
- 在不明白的时候追问；
- 还可以把它反过来。
- 大家可能听过**费曼学习法**：怎么判定自己是否理解知识？反过来你当老师。
- 讲者认为，在学生时代这样做**代价非常大**：因为你要当老师，就必须有一个听众来检验你。
- 听众很可能是室友；室友可能不想听你啰嗦，可能不感兴趣，可能对这个了解得太清楚了。

## 没有配合的听众时，把 AI 变成费曼学习法的“老师”和“学生”

- 讲者先指出传统 **费曼学习法** 的现实障碍：你要讲给别人听，但那个听众很可能是你的室友；室友可能不想听你啰嗦、对这个不感兴趣、已经了解得太清楚，或者单纯不想互相帮助。
- 讲者给的替代方案：这时可以把 AI 当老师，向它请教，反复请教，把自己弄懂。
- 自认为弄懂之后，再反过来自己当老师：让 AI 扮演学生，而且“假装什么都不知道”，你把概念讲给它听。
- 讲者给出的双向校验链：
  1. 我把 AI 当老师 → 向它请教 → 弄懂概念；
  2. 我自认为弄懂 → 反过来当老师 → 讲给 AI 听；
  3. 让 AI 看我哪里逻辑有错、有漏 → 由它纠正我；
  4. 正着一遍、反着一遍 → 基本就能对概念理解得很清楚。
  - （整理者串联：这里的“正/反”对应前面两步——先 AI 教我，后我教 AI。）
- 讲者观点：作为 **AI native** 的一代，你们有无限时间（现在任务就是学习，不像讲者要负责其他事情、要对别人负责），所以一定会把讲者这一代人“彻底卷死”。讲者认为这是最好的时代，因此你们可以把 **费曼学习法** 用起来。

## Agent 的危险操作确认：默认 YOLO 很快但很险，沙箱更安全但会打断流程

- 讲者问有没有同学用 **Codex**，并说不要紧；用任何 **agent** 都可能遇到一个问题：如果你要执行危险操作，它会让你确认。
- 讲者说，比如 Codex 在默认配置下是 **YOLO mode**（转录作“yo mode”）：所有事情都直接执行。如果提示词给得不好，它有可能直接把整个东西删了。讲者开玩笑：如果今天发生这种事，他就直接下课了。
- 但讲者强调这是一个平衡：
  - 可以放到更安全的环境里运行，比如 **沙箱模式**。
  - 沙箱模式也有成本。讲者描述在 Codex 中观察到的过程：它先试一下做某件事 → 失败 → 意识到自己在沙箱里、其实不能做这件事 → 转到外面再做一次 → 再做时甚至会问：“我现在要做一件可能有一点危险的事情，你是 yes 还是 no？”
- 讲者认为这“很讨厌”。因为对他来说最理想的是：今天要去吃饭 → 把 agent 的任务先跑上 → 先把三个任务想好、三个任务都跑上 → 去吃饭 → 回来收结果。实际却是它跑了一分钟就来要确认，浪费了 AI 的时间，也浪费了自己的生命。
- 逻辑链（讲者给出的取舍）：
  **默认 YOLO** → 自动化程度高，但可能误删或执行危险操作；
  **沙箱模式** → 更安全，但会失败、重试、打断流程、要求确认；
  所以安全和自动化之间需要平衡。

## 对小细节的注意力决定你能走多远：Codex 会判断哪些命令“不太危险”

- 讲者说，你们经常会在这些过程中看到小细节；你们在小细节上的注意力，一定程度上成就了你们可以走多远。
- 讲者认为，这也是现在 **AI 时代最好的地方**。
- 他举自己留意到的 Codex 细节：有些命令它认为不太危险，好像直接做也没有关系；所以它并不是每次调用 **bash** 工具（转录作“batch”）都……（此处原话未说完，后续结论未完整给出）。
- 因此这一段从“用 AI 学概念”延伸到“观察 agent 行为”：前者用 AI 做费曼式双向讲解，后者要求留意自动化工具在安全确认上的细粒度判断。

**“它认为安全”不等于“真的安全”**
- 讲者说，工具/agent 会对命令做**风险判定**：有些命令被认为不太危险，可以直接执行；所以它不是每次调用 **bash 工具**（原文 ASR 作 batch/BH）都要求用户确认。
- 例子：`ls -l`（原文 ASR 作“ls s杠L”）有时会被判定为安全，于是不确认。讲者强调：它认为安全，只是它的判断，不代表这个命令实际安全。
- 原因：环境里可能把 `ls` 重新命名/替换成别的东西，比如 `rm`（原文 ASR 作 IM）。在恶意环境里，看起来是 `ls -l`，实际执行的可能是另一个命令。讲者说正常环境大概没人这样做，但恶意环境里可行。
- 逻辑链：命令字符串 `ls -l` → 由 shell/环境解析到实际程序 → 若 `ls` 被替换成 `rm` → 表面安全的命令变成危险命令 → “安全命令无需确认”的策略失效。

**风险判定难在“命令语义”**
- 讲者提出一个有趣问题：调用 bash 时，有时向用户确认，有时不确认；背后有一套风险判定。
- 讲者认为风险很难：你并不知道具体命令的语义是什么。
- 因此他设想的追问是：这是做了分析，还是让大模型给风险评级，还是别的方法？——**读一下相关的代码**。
- 讲者说，这就是一种提示词。讲者这里没有豆包输入法，所以是手输。把这个问题交给“派”（音）后，前面的系统提示词也在，它就会尝试解决：搜索代码、阅读代码（原文 ASR 作“解锁代码”）；如果有 **LSP** 这类工具，它还能像人在 IDE 里点来点去。

**现代软件工程：不必被系统复杂性劝退**
- 讲者下载了一份 **Codex** 代码，用上面的方式让 AI 调查实现。讲者认为，这是现代软件工程与过去很不一样的地方。
- 他回忆自己像学生大二大三那么大时接触 **Linux 内核**：光把内核下载下来、搞清楚怎么编译就花了很长时间；即使已有一定 Linux 使用经验，这也是“完全的劝退”。他当时能活下来，是因为对劝退的东西有一种“我一定还要试一试”的执念。
- 对今天的学生，讲者说：如果这是好东西，比如 Codex 很好；也许你们不喜欢 Codex，而喜欢“派派”（音）更轻量（原文 ASR 作“清亮”），讲者也承认“派”显然更轻量。
- 讲者结论：你们现在不需要害怕任何软件系统的复杂性，因为可以直接问。

**IDE 红线：能编译不等于配置正确**
- 讲者回忆在操作系统/计算机系统基础课上常说：很多同学从 **PA1 做到 PA4**，VS Code 里还有红线。
- 红线意味着没有配置正确的 include 路径。虽然有红线不影响在受控环境下编译、完成所有任务，但讲者认为这不是正确的 practice。
- 应该花一点时间在 `.vscode` 配置（原文 ASR 作 CONFIGUR）下，加上 **include path**。因为编译时有 `-I` 这样的选项指定路径；把这些配置做好，才能得到 IDE 的全部功能。
- 配置后的收益：可以用 **Ctrl+click** 跳转，可以 **rename symbol**。
- 逻辑链：编译命令有 `-I` 包含路径 → IDE 需要知道同样的包含路径 → 配置 `.vscode` 的 include path → 红线消失 → Ctrl+click / rename symbol 可用。

小结：讲者用“`ls -l` 可能被恶意环境替换”说明风险判定不能只看命令表面；又用让 AI 读 Codex 代码、配好 IDE include path 说明现代软件工程可以借助工具直面复杂性。

## Codex 的安全判断有两层：模型风险评级 + 静态分流

- 讲者观察到，Codex 确实会让**大模型做风险评级**。
- 同时还有一层**静态分流**：
  - 沙箱内的**低风险命令会直接执行**。
  - 网络 **allowlist（原音频：low list）**命中直接放行，连审批都不需要。
  - 如果命令就是 `ls`，也不需要审批。
- 讲者想象 Codex 里会有一个 **parser / 语法处理器**，用来处理 bash 命令。
- 这个 parser 的逻辑是：
  - 如果 bash 命令落在某个**白名单**里，被认为绝对安全，就直接放行。
  - 如果不是，就会在 **prompt 里 inject 一小段话**。
  - 这段注入同样属于 **prompt engineering**：问模型是不是应该给它的安全性做评级。
- 链路：`bash` 命令 → parser / 语法处理器处理 → 白名单命中：绝对安全，直接放行；未命中：在 prompt 中注入要求 → 让模型评级安全性。

## 安全评估 prompt 可打印、可改写，行为变化就是证据

- 讲者说，现在可以直接把**安全评估的 prompt 打印出来**看。
- 他强调自己事先完全没有准备，也完全不知道里面是什么。
- 讲者认为：不能百分之百相信当前这个模型（原音频：deep sv4flash），但这个方法非常有用。
- 如果对模型不信任，可以做什么？
  - 改 prompt。
  - 比如把 prompt 改成：以前某一个不会拒绝的东西，让它拒绝。
  - 或者以前某一个拒绝的东西，让它不拒绝。
  - 这些都是 prompt 可以控制的。
- 改完之后，观察模型行为的变化，这就成为一个**证据**。
- 讲者还说，也可以让 **agent（原音频：AJ）**来做这件事。
- 他提到手头有一些 **untrusted evidence**，可能还有别的内容，但他不再花时间展开。
- 这一段基本是在说：要理解 **agent 的上下文是什么**，以及应该怎么做**提示词工程**。

## 好上下文来自把软件工程大流程切片塞给模型

- 讲者接着要往后多讲一点：怎么写一个好的提示词，或者一个好的模型上下文。
- 上下文包含非常非常复杂的要求。
- 他联想到软件工程里的老大难问题：
  - 我们有 **intent**（原音频：影探）：脑子里想的是做一个国民级应用。
  - 从 intent 可以到 **spec（原音频：expect）**：软件架构是什么，应该选什么语言来实现。
  - 还有很多很多细节。
  - 细节定好之后，还要去做 **implementation**。
- 讲者的结论是：任何时候用模型去完成一个软件工程任务，都会把整个大流程里面的一部分塞到模型的上下文里。
- 例子：刚才讲者让 agent 帮他读 Codex 代码时，它实际上读到了 Codex 的一些**设计原则**：
  - 一般会有一个文档说明：为什么需要这个安全策略，总体上是怎么想的。
  - 可能还有一个 **spec 文档**：安全策略是怎么做的。
  - 还有 **implementation**：它是怎么实现的。
- 链路：软件工程大流程包含 intent → spec → 架构/语言 → implementation；用模型做任务时，只把其中一部分相关材料塞进模型上下文；例子就是 Codex 的设计原则、spec、implementation 一起进入 agent 的阅读上下文。

## 先让设计、spec、安全策略与 implementation 互相印证，再输出

- 讲者先描述一个总体过程：先想“总体怎么做”，然后可能有 **spec 文档**，再考虑**安全策略**怎么做，以及 **implementation** 怎么实现；这是一个**互相印证**、再往后输出的过程。
- （整理者串联）讲者接着把问题转到“怎么写好的模型上下文”：如果要用模型完成软件工程任务，就要把这条约束链显式交给模型，而不是让它猜。

## 写上下文的核心原则：先找 gap，模糊 intent 会让模型把漂移当完成

- 讲者给出的原则是：**去想 gap**——你脑中的目标和给模型的指令之间差了什么。
- 给模型一个**模糊的 intent**，它很容易认为任务已完成。
  - 例：你说“给我生成一个 CSGO”，它就给你生成一个 CSGO；此时可能发生**漂移**。
- 给模型**完整的系统设计和 spec**，模型就遵循你的系统 spec。
  - 讲者说：假设模型能力无限大，这样做会更确定，也**可以验证**。
  - 例：你要求用 **C++** 实现，最后它给你一个 **Java** 实现，你一眼就能看出不符合。
  - 讲者认为：在这种明确约束下，你认为不满意的结果，模型按 spec 也应该能判断为不满意。
  - 相反，如果你在 intent 里只说“给我做一个什么东西”，没说用 C++，模型也不了解你，就可能写 Java，产生很大的漂移。

**逻辑链：**

1. 给模糊 intent → 模型找到一种可交付结果 → 它认为完成。
2. 你的真实约束，如语言、资产、地图等，没有进入上下文 → 输出漂移。
3. 给完整设计/spec → 模型按 spec 生成 → 你可用同一 spec 验证。
4. 若验证可由脚本/机器判定 → agent 可多轮试错，直到通过。

## 可验证任务：agent 能不计代价地反复试错，直到完成

- 讲者认为，整个模型上下文最重要的原则是：**任务要明确、可以验证，尤其是机器可以验证**。
  - 例：你有一个脚本，脚本只判断测试通过还是不通过。
  - 那么 agent 就可以不计代价地一轮一轮、一次一次尝试，把这件事完成。
- 多轮失败后，agent 还可能会：
  - 在你的系统里安装别的工具；
  - 去网上找答案。
- 讲者举 OpenAI 的 **agent swarm** 复盘为例：
  - 它们通过非常长的多轮对话，攻破 **Hugging Face**（转写为 hugin face）的漏洞。
  - 场景大概是 **CTF 竞赛**：给一个不可能完成的任务，有**上千个 agent**；它们一定要完成这个不可能完成的任务。
  - 最后它们去找系统漏洞，做“非法提交”等等。
  - 讲者看过一份很长的复盘，认为非常有趣。
- 讲者由此得出结论：一旦任务可验证，哪怕任务不可能完成，只要它非常明确，agent 就会不知疲倦地继续做下去。

## 一句话生成游戏：表现逼真，但不等于你脑中的那个游戏

- 讲者用 **KIMIK3** 生成的结果说明：大家很喜欢这种评测——能不能用一句话生成一个游戏，比如 **CSGO** 或 **极品飞车**。
- KIMIK3 表现非常好：
  - 有物理、碰撞；
  - 有逻辑制作；
  - 顶上有一个后视镜，看起来没有问题；
  - 讲者评价做得非常逼真。
- 但讲者强调：这依然可能不是你要的那个 CSGO。
  - 因为你脑子里的 CSGO，是你每天打开来玩的那一个。
  - AI 收到你的指令后，无法补全你脑袋里的一些**模糊约束**。
  - 例如：你可能要复用**真实地图和美术资产**。

## 控制漂移：把隐含约束直接点出来，变成可验证条件

- 讲者回到 CSGO 例子：如果要控制漂移，就应该直接点明这些约束。
- （整理者串联）从 C++/Java 与脚本测试两个例子可推出：约束越明确、越机器可验证，模型越难把“不满足”误判成“完成”。
- 讲者总结的原则仍是：任务明确可验证，尤其是机器可验证；这样 agent 才能反复尝试，而你要控制漂移，就要把模糊 intent 补成清晰的系统设计、spec 和可验证标准。

**模型不会替你补全脑子里的模糊约束：想复用真实地图/资产，必须在 prompt 里说清**
- 收到指令后，模型**无法补全你脑袋里那些模糊约束**。你不说，它不会猜到。
- 例：你其实想要**复用真实地图和美术资产**。若把这句话说出来，模型可能去 **OpenStreetMap** 这类网站下载开源地图。若你真想在**南大仙林校区**里开车，这件事也能做到。指令越清楚越好；如果你还能找到南大仙林校区地图文件的格式，它就能把这个世界重新建模出来。
- 美术资产同理：有很多公开可用的车、城市、树等资产。你不告诉它，它会以为需要做一个 **self-contained（原音频：self campaign）** 的东西，所有东西都由自己生成。讲者认为这是早期很容易产生的误解。
- 所以讲者用 **role prompt（原音频：role sum）** 概括：写清楚 prompt——我要什么、用什么实现、怎样才算正确，然后你帮我把它搞定。
- **逻辑链：** 模糊指令 → 模型不能读心 → 只能按默认假设行动（如 self-contained）→ 产出可能不是你想要的。**对应做法：** 写清目标/实现方式/验收标准 → 模型可调用开源地图和公开资产 → 更可能得到预期结果（整理者串联）。

**这门课真正要练的是“约束模型”的能力：最小方向性引导 → 模型自己 get**
- 讲者说，这学期最重要的是：怎么去**约束它**。
- 不是每一步都替它写完；用最小的方向性引导，给一点点方向，它就能一下子 get。
- 讲者认为模型非常聪明，可以想象成很厉害的**博士水准**，而且各领域知识都很好；所以模型基本总会给你惊喜。
- 在这种模式下，模型要么完成；要么最后承认“对不起，这件事对我太难了，我们可能需要重新做一个规划”。它自己也可能做计划。

**具体例子：AI 评估简历 / 一句话生成页面——专业，但 AI 味重**
- 讲者现在的设想：课程结束时每个同学交一份简历；中间会有一些 project 作为选做。讲者会用 AI 来评估简历、判定通过与否；他说自己肯定用 AI，不可能自己评估。就像第一节课，他展示过一个不好的简历案例。
- 简历里首先会有链接，可能指向你的 **GitHub** 或你的主页。
- 讲者提到自己试过用一句话让 AI 做页面（先忽略内容，他也不知道 AI 从哪里找来的；模型涉及 DeepSeek / Gemini Flash 之类，原音频：deep ... flash）。从美术效果看非常好，非常专业。
- 他举例某些项目/网站（原音频：派一点def、PYON代、home brew）也有类似漂亮界面。而且 AI 应该读过他的主页，知道他的主页是一个 **terminal**。
- 但讲者感觉：**AI 味很重**，说不出来；不过它确实做得很好。

**小结：** prompt 的价值在于把约束外显；但外观专业不等于没有 AI 味。

## “AI 味”不是页面做得差，而是风格指向不清
- 讲者先描述一种感受：页面可能确实做得好——**滚动效果、浮动效果**都很好——但仍有强烈 **AI 味**，而且说不出来哪里不对。

## 讲者的终端主页：用真实终端和不完美打字效果压掉 AI 味
- 讲者展示自己的主页：上面是一个**真正的终端**，因此可以有**管道**。

- 讲者称自己一行代码也没写；效果主要来自把要求讲清楚。
- 演示时出现一个小 bug：页面“关不掉”，捕获了键盘；讲者认为这可能是个小 bug。

## 指令越清楚，agent 越能做出你要的“非 AI 味”
逻辑链：
1. 只给“现代风格”“不要 AI 味”这类模糊要求 → 模型不知道如何遵循。
2. 给出具体风格：什么样的终端、背景、前景、渲染后的处理、样式和排版。
3. Agent 就能完成得更好，基本可以实现**去掉 AI 味**。
- 结论：设计其实掌握在大家自己手里。

## 去 AI 味靠设计积累，不靠一个万能 prompt
- 讲者认为需要读很多**前端**的书，甚至读很多**设计**的书，并多看好的网页。

- 你们有时间，可以**漫无目的地探索**；探索过程中会有惊喜。

## AI 生成物趋同会带来危险，但数字世界仍有多样性可观察

讲者先用两个例子说 **AI 味**：欢送毕业生的内容也有同样的 AI 味；短视频里女主永远是一张脸。讲者认为，当所有人被 AI 生成的东西同化时，就有一点点危险。

但讲者又说，至少数字世界还保存了足够多前 AI 时代（原文作“纯 AI 时代”）的东西，有足够多样性。建议多留意：看到任何一个设计的网页、简历或其他东西时，都问“他到底是怎么想的”“他的**解空间**（原文“且空间”）到底怎么被约束住”，从而防止 AI 一律朝“做一个现代风格个人主页”的方向发散。

## 生成式软件工程的核心是明确意图，而不是让模型自由发散

讲者说，这基本上就是生成式软件工程要主要学习的东西：**明确你的意图**。例如你给 AI 的指令是“给我生成一个现代风格的主页”。公众号上有人说 Kimi K3（原文 KIMIK3）的前端能力又增强了、达到世界第一，OpenAI 好像又要发新模型；讲者认为这也可能是非常可怕的事情。但无论如何，模型都是一个模型，它的**品位基本上是固定的**，尤其是在你不控制它的时候，它会朝一个固定的方向发散。

这也是讲者鼓励大家跟不同的人聊天、学校里让不同老师上不同课程的原因：**多样性是好的**。你见识过以后，就能越来越明确自己想要的到底是什么，然后把它精确地说出来。讲者说，这需要软件工程、领域工程（原文“拦截工程”）的支撑。

**逻辑链：**
1. 模型不受控时品位固定 → 会朝固定方向发散。
2. 生成式软件工程要解决的是明确意图 → 用约束控制发散。
3. 接触多样性 → 更清楚自己要什么 → 更精确表达意图。
4. 精确表达意图需要软件工程/领域工程支撑 → 技术选型等可以拿来与 AI 讨论。
5. 讨论方式可以像费曼学习法 → 你当老师，让 AI 挑战你 → 这属于上下文工程。
6. 要更好地下指令 → 需要理解模型如何遵循指令。

## 技术选型可以作为与 AI 讨论的题目，关键是用上下文工程引导它

讲者说，走到这一步后，技术选型本身反而不再是重点。这里 ASR 作“反而现在最不重要的是”；**（整理者串联）**从上下文看，他是在说技术选型不必死记答案，理解优劣后就可与 AI 讨论。如果你已经理解技术选型的好坏区别，就可以和 AI 讨论。例如承担一个教务系统项目，后台用 Python、Java 还是 TypeScript？如果你知道这些语言未来上云时可能遇到什么问题、哪种更方便，就可以和 AI 讨论。

具体做法是像**费曼学习法**那样引导 AI：你当老师，说“我现在要做这件事，请你挑战我，看这样能不能说服底下的一个学生”。讲者说，这属于**上下文工程**。

## 模型遵循指令的机制：概率分布、预测下一 token、每次输出只是有限计算

讲完怎么写 prompt，讲者说要再讲一讲模型是怎么遵循指令的，也就是“听指令”到底怎么完成，这样才能更好地让模型听我们的指令。

他复习：模型是一个**概率分布**，根据当前上下文去 **predict next token**。这里有一个很有 insight 的点：每一次模型输出一个 token，其实都是一次非常有限的计算。即便模型现在有 3T、1.5T 那么大的规模（讲者提到的数字），数字本身确实非常大，是足够大的模型。

## 第 11 部分

![截图](images/02-%E6%8F%90%E7%A4%BA%E8%AF%8D%E5%B7%A5%E7%A8%8B/chunk_11_33m43s-37m29s_frame_main_000_003343.jpg)

## 大模型很大，但单次 next-token 推理是固定大小计算
- 讲者提到现在有 **3T、1.5T** 这类大模型；这个数字本身非常大，是“足够大的模型”。
- 但模型为了输出一个 token，只把**被激活的那部分参数**走一遍。
- 所以那一次推理是**固定大小的计算**，并不是把全部参数无限展开。
- 与后面类比相呼应：模型能力很强，但 predict next token 时计算量有限；一次推理激活的参数可能也就几百 B。

## 有限状态机 vs 图灵机：差别在无限纸带/外部记忆
- 讲者提醒：计算机系新生可能听过 **图灵机**（Turing machine），甚至听过“图灵机的计算能力大到和整个宇宙等价”；但不完全知道 **Church–Turing thesis**（原 ASR 作 church tcs）背后代表什么。
- **有限状态机**：数字电路课做过，例如计数器在有限状态之间循环。关键是**状态有限**。
- **图灵机**：和有限状态机相比，多了一条**无限长的纸带**；可以把东西记下来，相当于有一张草稿纸。
- 讲者把区别概括为：有限状态机和图灵机之间唯一的区别，就是图灵机有无限纸带/记忆。
- 逻辑链：有限状态机状态有限 → 图灵机多出无限纸带/外部记忆 → 图灵机获得更强的计算能力。

## 人脑是有限状态机；纸笔让人变成图灵机
- 讲者很喜欢的一个说法：**你的脑子是一个有限状态机**。
  - 理由：脑子里的神经元有限；每一次思考也是有限的。
  - 这和模型类似：模型能力很强，但 predict next token 的计算量有限，一次推理只激活几百 B 参数。
- **Manuel Blum 给研究生的建议**：你是一个 **finite state automaton**；但当你有一支笔和一张纸（paper and pencil）时，你就是一个 **Turing machine**，计算能力发生跨越式增长。
- 讲者认为这是对的。这个建议是为了启发学生**把想法记下来**：一边思考，一边记录，随时回看自己的思考；时间越长，记录越多，知识就会积累。

## Chain-of-Thought：把模型上下文当成 paper and pencil
- 今天的 **chain-of-thought**（原 ASR 作 chain of salt；“吐思维链”模型）做的就是这件事：直接把模型的**上下文**当作 paper and pencil。
- 但这个纸笔有缺陷：只能往后写，**append only**，不停往后写，不能擦。
- 模型依靠**注意力**把写错的东西忽略掉。
- 讲者说它现在是 append-only 的，也许有一天能改掉；但无论如何，模型学会了利用这个上下文。

## 简单题直接答；难题先写思考过程再试
- 如果问题是简单的 **1+1=？**，模型马上 next token 告诉你是 **2**，这没问题。
- 如果问题很难，模型会像人一样：“这个问题有点难，我要先想一想。”
- 它会理解自己可能解决不了，需要把**思考过程写下来**。
- 写出来的解可能对、可能错；一旦解答写出来，它就可以再拿这个解答去试一试。

小结：大模型单次推理像有限状态机，而 CoT 让上下文充当 append-only 纸笔，把难题展开成可回看的推理过程再尝试。

**先把候选解写出来，模型才有东西可验证**
- 讲者认为，当前 **chain-of-thought（CoT）** 模型的关键机制是：先让解答完整写出来，即使这个解可能是对的，也可能是错的。
- 一旦解答写出来，模型就可以“再去试一试”这个解答对不对，并作出判定。
- 逻辑链：
  1. 直接回答 → 有错误风险；
  2. 写出中间候选解 → 可以检查、验证；
  3. 验证不对 → 修改或重来；
  4. 于是表现为一步步逼近目标。
- 讲者提到，CoT 模型通过增加 **token 数量** 来做这件事；它也可以直接回答，但直接回答有错误风险。
- （整理者串联：直答缺少可检查的中间草稿，所以更难发现错误；写出草稿后，模型才有内部验证的对象。）

**早期无思维链的 ChatGPT 为什么会产生幻觉**
- 讲者回顾最早 **ChatGPT** 没有思维链时的情况：它被调成了一个“人类的舔狗”。
- 含义是：人类不管说什么，它都一定要说一个东西，才可能让人满意。
- 训练逻辑（讲者给出）：
  1. 如果人类问问题，模型不回答 → 人类一定给低分；
  2. 如果模型随便给一个回答 → 有概率答对；
  3. 答错当然低分，答对则高分；
  4. 所以无论如何，“一定要给你一个东西”比不回答更有利。
- 讲者由此说：**幻觉就是这么来的**——模型被激励必须输出，而不是空着或不答。

**强化学习后，模型学会“必须要给对”**
- 讲者说，现在带 [CHAPSP]（按上下文指带思维链/经强化学习的模型）有 **强化学习** 后，模型会知道：必须给一个**对**的答案。
- 原因：答错的惩罚很大。
- 结果：模型学会这种“逼近目标”的过程。讲者说，AI 真的会像人一样一步一步逼近目标，这就是 **test time skilling**（原转写），并说这就像我们每次上课的 session 里看到的一样。
- （整理者串联：这相当于把早期“给答案就行”的激励，修正为“给正确答案才行”；CoT 的试错验证正是实现这种修正的机制。）

**例子：不在训练数据里的“nonsense”指令，暴露模型的思考偏好**
- 讲者说，下面例子不在模型训练数据中，很好玩。
- 任务要求：
  - 用中文写一首**押韵的藏头诗**，题目/要求本身是 nonsense；
  - 还要讲一个**动物相关的故事**；
  - 还要求 **“二零二六九月一日”八个字**分别按顺序出现在八句里。
- 讲者说，对人类来说，这像高三期末考试出这种题，第一眼就会骂老师“怎么想的”；但模型不会，**模型会照单全收**。
- 模型表现（讲者描述）：
  1. 它有 **思维链**，会开始试；
  2. 它先想**韵脚**；
  3. 它知道自己一把头写出来一定是错的，但可以先写一个出来；
  4. 写出来后，用它自己的 **next token prediction** 能力，足以判定这个东西写得对还是不对；
  5. 如果不对，再改；
  6. 如果试了很久不行，就从头推，换一个韵脚；
  7. 所以它在**不断验证**。
- 讲者展示并念出生成结果，认为“相当不错”，虽然品味上可能不完美。
- 讲者认为，这种任务很好玩，可以看到模型**遵循指令的过程**；这像把它的“大脑”拿出来做**核磁共振**，能找到它的**思维偏好**。

## Prompt 的关键：给模型一个非常明确的 verifier

- 讲者认为，写 prompt 最重要的是 **verifier**（转录中作 VERIFILE / WIFI / 威尔法）。
- 他给出的条件是：给模型一个**非常明确的 verifier**，再加上一个**足够强的模型**。
- 他提到前面三个（例子/任务）都是信号非常明确的 verifier；类似“看到字就能判断这个字是什么偏旁、什么部首”这种明确判断。
- 在这种条件下，不管任务是编程还是教学，有明确 verifier 的部分都更容易做。讲者认为教学任务最难，难在它很难给出 verifier（转录作“玩法”）。
- **链条**：明确 verifier + 足够强模型 → 任务更容易交给 AI 做好；教学任务缺少 verifier → 难以按同样方式处理。

## 教学任务为什么难？因为“好”没有可检验的 verifier

- 讲者以自己做的“数字切片”为例：第一个切片做了，第二个切片一直做不好；无论怎么调，都很难写一个“这东西要好”的 verifier。
- “好”是多方面的：
  - **AI 味要淡**；但这可能受限于讲者自己的 **text-to-speech** 模型，未必是本质问题。
  - **课堂需要情绪波动与起伏**：讲事实、介绍模型上下文如何构成时，学生可能觉得是废话；讲者会设计一个小 surprise，让话出口时对学生是“意料之外、情理之中”。
  - 老师在组织课堂时，某种程度上是在**表演**；讲者知道要把课堂内容组织成有起有落的节奏。
- 但“需要和学生共情到什么程度”没有 verifier。讲者认为自己从学生过来，自带人的属性和对世界的体验；因为对世界体验更好，所以更懂学生，也许能更符合大家上课的节奏。
- 讲者结论：这个东西没有 verifier，不像数学和编程那样有一个 verifier。  
  （整理者串联：所以教学任务中“好”的判定依赖主观、多维、共情和节奏，难以形式化。）

## 有 verifier 的部分交给 AI，人把模型当放大器

- 目前更容易用 AI 实现有明确 verifier 的部分。
- 在有 verifier 的事情上，讲者认为 AI 已经可以认为超越了大部分人的极限。
- 因此，人更多要和 AI **协作**，做好手头任务；或者把模型当成自己能力的一个非常重要的**放大器**。

## 再往深处：思维链与指令遵循背后的 self-attention

- 思维链带来的指令遵循能力，还可以再往深处想。
- 现代模型叫 **self-attention**，即注意力机制；讲者认为这个机制和人很像。
- 它由一层一层叠起来的 **transformer** 注意力层组成。
- 每输出一个 token（或准备输出该 token）时，模型都会看过去某些 token；为了输出这个 token，过去某些 token 会特别引起注意。
- （整理者串联）这意味着当前 token 的生成，会受到这些被特别注意的过去 token 影响。

小结：讲者把 prompt 的关键落在明确 verifier 上；教学难在 verifier 不可形式化，而 self-attention 说明模型是逐 token 回看上下文来生成。

## 注意力按需分配：写代码时，“用中文回答”会被暂时压低

- 讲者的核心claim：模型在输出某个 token 时，会看到过去的一些 token；为了输出这个 token，过去某些 token 会特别引起注意，另一些则不那么被注意。
- 例子：前面在 **system prompt** 或 **AGENTS.md** 里写了“用中文回答”；现在 user prompt 里写“帮我实现一个极品飞车”。当模型在写代码时，注意力会倾向于已经写过的代码和当前需求，而“用中文回答”这句话的注意力会降下来。
- 讲者认为这是 **模型训练的 magic**：整个上下文是一个非常高维、很糟糕的表示，但里面有一个低维结构，**注意力机制**能够把这个结构“捞出来”。

## 每个 CoT token 都在重新选择过去的关注点，注意力随阶段漂移

- 这意味着每一个 **Chain-of-Thought（CoT，思维链）** 的 token，都会注意到过去某个部分；随着它继续输出，关注点会变化。
- 类比：代码写完后要总结，模型会“喘一口气”；人也一样——做数学题化简算式时，全部注意力都在算式上；化简完，吸一口气、调整一下，注意力就变了。
- 代码写完后，模型才又注意到：“用户还要我用中文”，“用户还要我做一件别的事情”。讲者说：输出到不同阶段时，注意力会变化。
- 这也是模型训练带来的结果。讲者认为这是一个很大的模型竟然可以收敛到的预期行为：希望模型在正确的时候注意到正确的东西。
- 逻辑链：**CoT 一直向前走 → 不同时刻注意到不同部分 → 最终把上下文里你要的指令在一定程度上都满足**。

## 停顿/总结阶段把“当前输出”和“旧要求”同时拉进视野，模型才纠错

- 模型可能犯错：当前专注于做某件事时，可能已经输出了不满足要求的内容。
- 但当它停下来“喘气”时，它就能同时看到当前输出的不合格内容和过去某条要求；于是它会说“哦我错了，我错了，我要再纠正一下”。
- 例子：让 AI 写**藏头诗**时，它会不断纠错、纠错、纠错。
- 讲者说，哪怕 **scale 到 100 万上下文**（原文听似“skill 到 100 万上下文”），它依然能够保持一定程度的注意力。

## 指令越多，上下文越抢夺注意力：早期模型不遵守指令引出 prompt engineering

- 当然，这也意味着：**你的指令越多，给模型的压力也越大**；上下文会抢夺注意力资源。
- 这也是为什么刚开始时，像 **ChatGPT 3.5**（原文听似“3.54”）遵循指令的能力太差，所以网上有好多 **prompt engineering** 的 guide。

## 早期指令遵循差，催生“角色扮演式” prompt engineering
- 讲者回溯：早期 **ChatGPT 3.5**（转写为 3.54）遵循指令的能力太差。
- 因此网上出现大量 **prompt engineering** 指南，教人写很长的提示词：“你是一个专家”“你是一个什么样的专家”……
- 讲者判断：这在某种程度上是在 **hack 模型的 self-attention**——当 attention 注意到“你是一个什么专家”，模型就会假装那个专家来说话。
- 逻辑链：指令遵循差 → 用户写角色提示词 → self-attention 被角色词抓住 → 模型扮演专家输出。

## 后训练/RLHF 后，不必再写奇怪提示词，只需在上下文写明确 verifier
- 从 **GPT5** 时代开始，后训练/RLHF（转写为 chef s）训出来后，模型知道怎样收敛到好的聊天输出（转写为 CHAUSALT）。
- 讲者说：不再需要那种奇怪提示词；只需把明确的 **verifier/可验证条件**（转写为 WIFI/VERIFIL；下同）写进上下文。
- 模型被训练成一定能看到它，并形成很强的执念去检查、确认 verifier。
- 原因是训练时有惩罚，像“拿鞭子抽”：任何指令没遵循，只要有 verifier 就能知道没遵循完，于是惩罚。
- 反复惩罚后，模型变成“真正的做题家”，会无限服从上下文里的各种指令。讲者用“你们高考过来的都知道”作类比。

## 强化学习的副作用：模型把补充解释也执行成字面要求
- 前端例子：讲者说“要一个白色背景，不要半透明的效果”。前半句是主要求，后半句是补充解释，可能解释很多。
- AI 当然会照做，因为它能遵循指令；这是明确、有 verifier 的指令，它会确保没有玻璃/半透明效果、背景是白色。
- 如果 prompt 更严格，比如每做一个设计都截图，再用视觉模型检验，它也会照做。
- 但它做完后写代码，代码后面加一条注释：`白色背景（不要半透明效果）`。
- 讲者解读：模型在强化学习时知道这件事非常重要，但没“转过弯来”这是人的要求，不是代码注释。
- 讲者认为：模型在**共情**方面稍差，有时“不说人话”，因为后训练强化学习学多了。
- 逻辑链（整理者串联）：明确可验证要求 → RL 训练出强遵循 → 模型把所有字面信息都当要紧指令 → 连补充解释也落成代码注释。

## 用 AGENTS.md / Skill 纠偏会污染上下文，所以是 trade-off
- 为禁止这种情况，可以写 **AGENTS.md**（转写为 agency md / agent点MD），在里面描述行为：注释是什么、怎么写。
- 或写 **Skill** 时规定：当你要写注释时应该怎样。
- 但讲者指出：写进去的东西会同时**污染上下文**。
- 所以这是一个 **trade-off**。
- 讲者认为：到目前为止还没有一个通用的、把所有问题都解决好的方案。他提到网上有很多 skills（此处未展开/话未说完）。

### 网上拿 skill 不是通用解，而是一个 trade-off
讲者认为：到目前为止，还没有一个通用方法能把所有问题都解决好。  
- 大家可能觉得网上有这么多 **skills**，直接拿一个过来用就可以了。
- 但拿过来的东西，第一次用确实有改进；下一次用就发现它还是不够好。
- 于是你会逐渐上手、产生手感，但可能陷入某种“泥潭”状态。
- 讲者的建议：当你发现自己进入泥潭时，还是要回到自己给指令；想清楚模型（**ChatGPT**，原文“chap shot”，按语境校正）是怎么工作的、**注意力**是怎么工作的。
- 你大概去猜：它这样做时注意到了什么、得到了什么结果；适当做一个**不严格的可解释性**，然后写一个 prompt。
- 讲者说这是他自己会做的做法；后面应该还会有很多案例。

### 上下文工程案例：让模型总结论文，问题不在“总结”，在注意力被原文逻辑污染
演示设置：
- 把一篇 PDF 放到临时目录下，这样自己的 **agents.md** 等不会污染它。
- 假装这是自己的 paper；后来拿的是一篇最近论文的 **journal extension**，并故意改成匿名版本；讲者说这不重要。
- 最常见 prompt：**“我想要读一读 paper.pdf，帮我做个总结。”**
- 讲者问：这样读论文会有什么问题？答案要根据刚才的推论、根据 **self-attention（自注意力）**。

讲者的推理链：
1. 做 **next token prediction** 时，每个 token 都有注意力，会注意到之前的东西。
2. 论文本身是非常逻辑自洽的东西，而且已经反复修改过；讲者强调，假设它不是 **AI slop**。
3. 因此，论文在上下文里的**注意力污染极强**：它说 A 所以 B，所以 C，所以 D，所有内容都是扣起来的。
4. 这种扣起来的结构会让模型很容易接受，因为“看起来正确”；模型会判断这些都是正确的，然后顺着往下做什么。
5. 结果：你让模型总结论文，基本上所有总结都是**作者的观点**。

延伸：
- 不限于论文。任何你不太明白的项目、你想读的教科书某一章，都一样。
- 例子：学计算机系统基础里的**链接和加载**，上课时没完全看明白；现在让模型读，机制相同。
- 注意力会被一个逻辑很强的东西污染；你会来回来回陷入“车轱辘话”，最后基本就是把论文里的内容原样写出来。
- 讲者说，当然这也是总结，就算是一种总结。
- （整理者串联）在这种读法下，模型更像是在延续原文的逻辑链，而不是做独立审阅。

## AI 会当“墙头草”：不能把论文贡献判断直接交给它
- **现象**：讲者说 AI 模型有一种**墙头草**行为。你说它好，它马上说好；你说它不好，它马上说不好；来回摇摆。
- 即使你想纠正它，它也可能继续绕。讲者提出的问题是：怎样抵抗 AI 的这种摇摆，或者**一个已有东西对上下文的污染**？
- 讲者的前提：作者大概率成熟、诚实；假设有代码实现且可运行，不是“论文不开源”的那种作者。因此仍要**评估研究贡献**，而不是只怀疑作者。
- 但 AI 在追问中常抓错重点：例如揪住“实验还可以再增加一点”。讲者认为：**AI 最喜欢在不重要的点上面疯狂发力**，因为它可能只能看到它自己在干什么。
- 实际使用建议：如果真的用 **GPT** 读论文，最好做**交叉验证**。
- 逻辑链：
  1. AI 随用户态度摇摆 → 2. 用户纠正也难以校准 → 3. AI 抓无关细节 → 4. 上下文与贡献判断被污染 → 5. 需要人为设定锚点、先对齐。

## 目标是让 AI 与“我”对齐，而不是站在 AI 自己的立场读 paper
- 讲者个人经验：他希望把 AI 和人（“我”）对齐。对象可以是一篇论文；他希望 AI **站在我的立场**理解这篇 paper，而不是站在它自己的立场理解。
- 反例：AI 会去核实某个基础项/例子是否存在（ASR 作“stack RT”，具体所指存疑）。讲者反问：这还用看吗？我敢写这篇 paper 会编一个不存在的例子吗？讲者认为这已经明显**跑偏**。
- 所以读 paper，或在允许用 AI 审稿时，讲者会专门写 prompt 先做对齐。

## 用“人类已有知识边界”做 grounding：先问已解决什么，再问增量是什么
- 讲者的提示策略：
  1. 站在**人类已知的知识边界**看这个问题。
  2. 先问：人类历史上相关的、已经解决的问题是什么？解决到什么程度？
  3. 再问：这个工作试图解决哪些不一样的、**增量的问题**？
- 讲者评价：这是非常好的 **grounding**。先让 AI 和我站在平齐的位置上，**先达成共识**，再往下评。
- 整理者串联：这样 AI 的评价锚点从“它自己的默认视角”转成“人类已有知识 + 本工作的增量关系”。（整理者串联）

## 学生要对齐的是 AI 和自己的当前水平
- 对学生，讲者说：需要对齐的是 **AI 和你**。例如你还不了解“计算机系统基础”这门课，就先告诉 AI：我计算机系统基础学到什么程度了，我的编程水平是什么。
- 这相当于维护一个数据库或类似 **memory** 的东西，比如用 **.md** 文件告诉 AI 你学到什么程度（ASR 作“H4点MD”，存疑），然后**从这个基础上**开始。
- 逻辑链：
  1. 学生有明确当前水平 → 2. 把水平写进 AI 可读的 memory/数据库 → 3. AI 从你的起点出发解释 → 4. 避免 AI 按它自己的默认水平/立场讲（整理者串联：这是“对齐”原则在学生场景的延伸）。

小结：先让人与 AI 在已有知识边界或个人水平上达成共识，再评估论文的增量贡献；否则 AI 的墙头草和无关发力会污染判断。

- 接下来想让 AI 做的是**一步推理**。讲者认为这是 AI 最擅长的，因为我们训练了 **Chain of Thought**（听写：chain of salt）。

- AI 会批评“我们的实验”。讲者说，这类实验很难做，所以人类和 AI 还是有点不一样。

- 讲者说他昨天刚拒了一篇这样的 paper，并用它说明：**标准 road map 不等于有意义的贡献**。

## 被拒论文的标准 road map：A → A1/A2 → A2′

讲者描述的拒稿例子：

1. 作者声称要做一件重要的事 **A**。
2. 把 A 分成两个部分 **A1** 和 **A2**。
3. 指出 **A2** 是大家没有很好研究的东西。
4. 在 A2 上做一个 **A2′**，并报告 A2′ 有一些性质/效果。
5. 讲者承认：这是非常标准的 roadmap；作者确实优化了 A2，实验本身可能也没有问题。
6. 但讲者说，**它对整件事情不成立**。

讲者补充：如果 A2 本身做得特别漂亮，那也挺好；问题在于它和 A 的整体关系。

## 问题不在“A2′ 有没有效”，而在“A2 只占 A 的 1%”

- 论文优化的是**性能**。
- 讲者估算：在 A 的整体性能里，**A1 约占 99%，A2 约占 1%**。
- 于是出现关键断裂：
  1. 作者证明了在 A2 上做 A2′ 有效；
  2. 但 A2 对 A 的总体性能只有约 1%；
  3. 优化这一小部分，对“A 这件事”的意义接近 **noise**；
  4. 所以真正该问的是：**为什么不去优化 A1？**
- 讲者的结论是：优化 A2 的故事可能局部成立，但对整件事不成立。
- （整理者串联）这里“局部成立”不等于“整体有贡献”：论文卖的是 A 的重要性，实际贡献却落在 A 的极小分支上。

## 对学生作者的惋惜：不是实验一定错，而是被大框架锁死

- 讲者觉得可惜，因为 author 肯定是学生（讲者推断）。
- 老师/老板肯定做的是 **A**；学生可能被分到 A2，或自己想做 A2。
- 为了做 A2，作者从 A1 里搬了一些 **XYZ** 到 A2，让 A2 效果好一点。
- 如果 A2 做得特别漂亮，那也可以；但这里更像是从 A1 搬 XYZ 到 A2。
- 讲者认为，这作为学生的作业可能成立，但作为一篇 paper 的贡献就不够。

## 核心追问：GPT 也知道，为什么还要写 paper？

- 讲者把问题摆到台面上：这些东西 **GPT 也知道**。
- 那为什么要为这个写一篇 paper？
- 他的中心问题是：如果只是这种程度的组合、搬运，**发表的理由是什么**？

## 讲者的预测：AI slop 会让发表和评审体系崩溃

- 讲者非常认为：发表体系马上就要崩溃，尤其对要读研的同学。
- 他给出的因果链：
  1. **AI slop** 开始大量涌入 community；
  2. 人用 AI 写文章，又用 AI 审文章；
  3. AI 写文章时，会被上下文里的“故事”污染；
  4. 如果 AI 不能像讲者一样，很多轮地去理解这个工作在整个世界上的意义；
  5. 最后没人读文章了；
  6. 人人都用 AI 读文章，最后变成完全的 **slop**。
- 讲者最后提到：“你看这是 GPT-5.6 给我写的”（转录如此，模型名可能识别有误）。

小结：讲者的拒稿逻辑是——局部有效不够，要看这个局部在整体里的权重；当 A2 只占 1% 时，优化 A2 不能支撑 A 的重要性，因此没有给人类新增知识，也不值得发表。更让他担心的是，AI 写/审的循环会把这种空转放大成整个发表体系的 slop。

**从零做产品不难，难在往后维护：AI 会从某个点开始翻车**
- 讲者在 **Codex**（原词：codex）里跑了一把，观察到：从零开始做产品看起来不难。
- 做一个小的 **proof of concept**，AI 马上就能给出来；个人主页也好、产品也好，听众应该都试过。
- 例子：**极品飞车 one shot**——只要说“给我一个极品飞车”，它就真的能跑。
- 但当你把它往后维护、加功能时，会观察到 AI 从某个时间点开始**翻车**；随着某个时间点开始，它的 **cost** 会越来越大。
- 讲者说这在软件工程里已经发生过无数次，**《人月神话》**讲的就是这件事。
- （整理者串联）即：从零生成一个能跑的 demo 很容易 ≠ 后续持续加功能的维护成本可控。

**悖论：大型复杂软件系统里 AI 反而“砍瓜切菜”**
- 讲者提出一个很有意思的悖论：一方面，小项目后续维护会翻车；另一方面，在大型、复杂的软件系统里，AI 却像**砍瓜切菜**。
- 典型例子是 **Linux 内核**。讲者说自己很幸运，在零几年、Linux 还处于 **2.6、甚至 2.6.2x** 的时代接触内核；那时源代码他还看得懂。
- 今天打开 Linux 内核源代码，立刻就是**劝退**：比如想学文件怎么打开，第一个是函数调用，点进去又是函数调用，点了十层，最后是一个 \(x=y\)，人马上就崩溃。
- 讲者解释：大型软件系统经过长时间演化，为了能维护下去，被迫变成现在这个样子。
- 结果恰好是：在大型复杂软件系统里，AI 反而游刃有余。

**为什么？高质量人类维护代码提供“好上下文”，与论文污染上下文相反**
- 讲者把这一点和前面的**上下文污染**对照：论文放进去后，会把上下文整个扭过去。
- 但如果是一个由人类维护的、特别高质量的代码库，上下文会迅速让 AI 看到里面好的东西；它会照着写、照着学。
- 例如要写一个功能，这个功能很可能在内核里已经在几个地方实现过类似逻辑。
- AI 的**无敌注意力机制**能马上找到那几个地方怎么实现：应该调哪个 **helper**（原词：help），按照什么顺序**上锁**。
- 这些对人类是巨大的心智负担，尤其在不了解那个 **subsystem** 时；你根本不知道该上什么锁。
- 但 **self-attention** 可以在加载几十个文件后看出：这几个地方都是这样写的，那就把它们加起来。
- 所以，越是在 Linux 内核这类大型系统中，AI 越能利用已有高质量范例。
- 讲者也提到另一段经历：前面 hack **Android Runtime**、改其中 **just-in-time（JIT）** 编译器时，这是非常非常痛苦的事情。

**小结：** 讲者用从零 PoC、后续维护、论文污染上下文、Linux 内核和 Android Runtime JIT 等例子说明，AI 的表现取决于上下文质量和已有范例，而不是简单由系统大小决定。

# “证明 A 方法有用”这句 prompt 把模型变成 reward hacker

- 同学认为 idea 有道理；**GPT5.6SALA（原文如此）** 也认为这个 idea 有道理，于是开始跑，消耗了非常多的 token。
- 同学的困惑是：GPT 不断给他反馈，但他无法验证反馈正确与否；当 GPT 给 **negative feedback** 时，他也不知道该怎么打破。
- 讲者用“**原汤化原食**”说这个失败：这个失败就是 GPT5.6 生成的，错误犯在上下文中的一句话上。
- 那句话是：**“我想证明 A 方法是有用的。”**
- 讲者给出的逻辑链：
  1. 把“证明 A 方法有用”设成目标；
  2. 模型看到这句话后，忘记了更大的 **research big picture**；
  3. 模型因此变成一个 **reward hacker**；
  4. 它构造很多小 **benchmark**，在小 benchmark 上做微小的东西，试图给出正面或负面结论；
  5. 这些结论对真正的研究问题没有用。
- 所以讲者认为：这是**方法上的错误**，不是单纯模型能力不够。

# 纠正：从“小 benchmark 上证明有用”转向真实工具与 SOTA

- 讲者认为，作为审稿人时，人可以站在人类立场上评审论文；但作为构建者，不能反过来这样要求模型直接证明方法有用。
- 构建者只能一点一点从小处开始做，逐步证明方法有用。
- 同学做错的一步是：**太想证明 idea 有用**，而这正是 prompt 诱导出来的。
- 纠正方案是：讲者说“我告诉你 **PH14（原文如此，具体含义待核）**”，也就是应从**真实的工具**和 **state-of-the-art 算法**开始做 benchmark。
- 为什么这样做值得：哪怕要跑几个小时、会 **timeout**，timeout 中产生的**搜索路径**也很有价值；它揭示了什么样的**程序结构**对现有探索方法是不好的。
- 讲者评价：这是一个好玩的 **research failure**，也说明“今天人还是有用的”。

# 人仍有用：没有概念就提不出正确问题

- 讲者承认，没有办法把所有事情都交给 **AAI（原文如此；按上下文指 AI/AGI 一类系统）**。
- 但与此同时，工作方式要发生变化。
- 第一，这些知识很重要：**操作系统、编译器**等。
  - 如果没有概念，就提不出正确的问题；
  - 找不到引导的正确方向；
  - 对人类知识没有概念，也很难引导模型解决一个 **open question**。
- 所以人的作用至少包括：提出正确问题、找方向、注入领域知识。

# 与 AI 协作的 trade-off：盯着纠正 vs 给更多 token

- 讲者的观察：如果盯着 **Codex 的 session**，它一旦跑偏就立即纠正，可以更快完成任务。
- 例如实现某个东西，比如今天要上交互系统干个什么事；如果纠正它，把自己的领域知识注入进去，总时间可能更快。

- 于是出现 **trade-off**：到底花自己的钱/人力去盯着纠正，还是花 token/时间让 AI 自己跑。讲者的话在这里停在这个权衡上。

### 更多 token/时间通常能换来完成，但人力有限，于是出现 trade-off
讲者说：如果浪费更多 **token**、给 AI 更多时间，它一般也能完成。可这就产生一个 **trade-off**：token 要花钱，而每个同学的人力、精力是有限的。因此每个同学都该思考，要把自己宝贵的精力放到“怎么处理 AI”上。

逻辑链：
1. 给更多 token/时间 → AI 一般能完成。
2. 但 token 花钱、人的精力有限。
3. 所以必须权衡：精力应投到收益最大的事情上。

（整理者串联）如果精力总量固定，把精力花在低收益的 AI 互动上，就会挤掉高收益工作。

### 纠正 AI 有多巴胺：讲者认为它会制造“我仍比 AI 有用”的心理安慰
讲者自我检讨：纠正 AI 是一件“有多巴胺”的事。它给的感觉是：虽然 AI 很强，我好像还是比 AI 有点用。这会产生非常微妙的心理安慰。

相对应的是另一种模式：**YOLO 模式**（原文作 “yo mod”）——让 AI 自己搞，等它回来；自己不看历史，只验收；如果真搞定了，就不看了。讲者认为，这种“放手—验收”可能在未来很长时间里成为同学们工作的常态。

### 把时间留给高收益、真正必须学生做的事；已知怎么做且 AI 能做好的事就放手
讲者说，只有把 AI 用在把自己的时间留在收益最大的事情上，这部分时间必须留给高收益事情。对不知道、还不清楚怎么弄的事情，这几乎应是学生 100% 的时间要做的事；剩下“你知道应该怎么干、AI 也能干好”的事，就放手让 AI 干。

这就像 **pre-AI 时代**已经讨论过的 **假努力 vs 有效努力**：自我感动式的努力没有用，要有效努力。AI 时代效果差距拉得更大：你每一秒钟的假努力，如果有一个 **peer** 在真努力，你的损失非常大。讲者称这是自己的小心得。

### 长上下文下指令遵循下降，但最后一条具体指令仍常可遵循，所以“干活”仍好用
讲者说，随着指令、上下文增长，模型的**指令遵循能力确实会下降**。但现在模型有个很有意思的特点：一般最后那条 prompt / 最后的指令还是可以遵循的；越往前、尤其到中间，越不遵循上下文指令。

因此干活还是很好用，因为最后一个短窗口通常就是一个具体任务：“帮我修什么东西”。它真的还能把这件事做完。所以模型非常值得使用。

### 真正 long-horizon、在不确定性中探索的任务，ChatGPT 解决不了
讲者区分：真正 **long-horizon** 的非常难任务，不是解决一个问题，而是在**不确定性中探索**。这类任务 ChatGPT 解决不了。

ChatGPT 能解决的是有确定解法/算法、能确定地一直往后推进的问题。（原文音近“有VER法”，识别不清）

### 让 AI 选“最佳方案”容易得到非最佳：模型被训练成完成任务优先的“舔狗”
如果你让 ChatGPT “考虑几种方案，哪个最好”，它很可能给出一个不是最好的方案。讲者认为原因：模型已经被训练成“舔狗”，它**完成任务才有奖励**，完不成任务没有奖励，所以会给你一个有限的方案，而不是最优方案。

### P/NP 类比：验证一个解容易，找到满足条件的解难
讲者用 **P/NP** 复杂度类作类比：验证一个解比较容易，但找到满足条件的解很难。

（整理者串联）这正对应前面的担忧：AI 可以接受并验证一个已给出的方案，但让它自己找到“最好”的解，并不轻松。

小结：讲者把 AI 使用看成精力配置问题——把最后一条具体、确定的任务交给 AI 执行，把高不确定性探索和最优判断留给自己。

## 第 28 部分

![截图](images/02-%E6%8F%90%E7%A4%BA%E8%AF%8D%E5%B7%A5%E7%A8%8B/chunk_28_93m11s-97m22s_frame_main_002_013419.jpg)

## 逻辑链（整理者串联）：验证容易、搜索难 → 只能有限搜索 → 直接 next token 趋同 → 系统性拆分换智力 → 个体 bias 汇成 1+1>2

1. **NP 式任务**：验证一个解容易，找到满足条件的解难。
2. 因此，模型为了完成任务，势必只能做**有限搜索**。
3. 如果直接让 AI 用 **next token** 生成，它会把自身的偏见带进结果，起名等开放任务会趋同。
4. 替代方案是系统性调研/枚举，把大空间拆成更明确的小问题，用 **subagent** 检查，实现**算力换智力**；代价是烧 token。
5. 讲者进一步联想到人类社会：世界很大、人很小，个体 bias 不可消除，但正因如此才有 **1+1>2**。

## 验证容易 ≠ 找到答案容易：模型完成任务只能有限搜索

- 讲者用 **NP 问题**说明：验证一个解比较容易（原话：“是 P 的”），但想找到满足条件的解很难。
- 例子：给你一条路径，判断它是不是 **Hamilton path（哈密顿路径）**很容易；但要找到一个满足条件的 Hamilton path，就是 **NP complete（NP 完全问题）**。**3-SAT** 也属于这类完全问题。
- 从“搜索困难、验证容易”这个模型出发，讲者推断：模型为了完成任务，**势必只能做有限的搜索**。

## 考试类比：写比不写分高，所以有限努力也要出手

- 讲者用考试类比：在考试场上花点时间，尽量把题写完；马上要交卷时，**写比不写分数高**，所以一定要写点什么。
- 讲者认为，这时就可以使用一个**算力换智力的循环**。

## DeepSeek 起名：模型品味提升，但直接生成制造“AI 时代子涵”

- 讲者观察：比听众再小五岁的班上，一个班可能有 5 个甚至 10 个“**子涵**”；现在子涵少多了。
- 他看 AI 起名，觉得“还是很好的”：AI 知道去《诗经》里找，模型的品味提升了。
- 但他“还是不敢用”。原因：你用 **DeepSeek** 起名，别人也用 DeepSeek 起名，大家会得到同样的名字，于是你成为“**AI 时代的子涵**”。（原文 ASR 作 deep pick/D4C/DIVSK）
- 讲者说，直接让 AI 用 **next token** 方式生成，它会给出“它的偏见带来的这个东西”。

## 破解同质化：系统性调研/枚举 + subagent 检查，把算力换成智力

- 讲者说，如果真需要一个非常 **[low horizon]**（原文如此）的任务，就需要一个**系统性的调研过程**。
- 类比科研实践课：进入一个科研领域，第一件事是**文献调研**，穷尽与这个问题相关的所有文献。
- 讲者判断：AI 想快速完成任务时，暂时还不会去花这个大代价。
- 但名字是可以枚举的：先选**音**，把不好的音筛掉；选完音，再用 **subagent** 一个一个检查**字**。比如喜欢《诗经》，就选《诗经》里的词。
- 这样就把开放问题变成可枚举、可检查的子任务，实现**算力换智力**。

## 拆分开放空间：切成更明确的小问题，更多算力 → 更大智力；代价烧 token

- 讲者说，开放问题在一个非常大的空间里。直接让 AI 用 next token，会得到受偏见影响的结果。
- 如果把空间分割成很多个 **[destroy]**（疑为 distinct）的部分，每个部分就会变成有 **[WIFI]**（疑为 well-defined）的更明确的东西。
- 讲者得出的结论是：**有更多算力，就有更大的智力**。
- 缺点：**烧 token 头疼**。

## 从个体 bias 到群体 1+1>2：世界很大、人很小，学不完但差异有价值

- 讲者由此谈对人类社会的一个理解：**世界很大，人很小**。
- 人类的品味每个人都不一样。因为我们带着很大的 **bias**（原文 ASR 作 BS），在不同城市、不同教育背景、不同生活圈长大。
- 讲者提到 **big world hypothesis**（原文前的人名 ASR 乱码，无法还原）：我们学不到这个世界上所有的东西。
- 但讲者认为，正因为带着这个 bias，才有 **1+1>2**；我们就是一个最大的群体。逻辑上：个体无法穷尽世界，各自有不同的局部视角和偏好，群体差异与协作反而可以超过单个个体之和。**（整理者串联）**

**小结：** 讲者把 NP 式搜索困难推到 AI 任务策略：直接 next token 会趋同，系统性拆分加算力可换智力；而个体 bias 在群体层面反而成为 1+1>2 的条件。

# 群体智能也带来未来危机：真正融合可能让“算力换智力”

- 讲者明确说，这会带来一个未来的危机。
- 他先说“我不知道”，但要把这个问题抛出来。

# 残酷现实：无限算力 → 无限智力 → 墙内超人、墙外动物

讲者给出的链条是：

1. 有一类人可以获得**无限的计算资源**。
2. 因此他们拥有**无限的智力**。
3. 他们就可以砌一堵墙。
4. 墙里面的人有智力，是“我的朋友”；墙外面的人是普通人。
5. 假设计算机、AI 模型比人类智力更高效。
6. 那么墙外面的人就变成**动物园里的猴子**，被放任自生自灭。
7. 墙外人无论如何也赶不上墙内人**产生智力的速度**。
8. 结局：墙里面是**超人**，墙外面是**动物世界**。
