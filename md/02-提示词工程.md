## 1. 提示词是模型看到的整条上下文，不只是对话框里那句话

<small>▶ [00:00](https://www.bilibili.com/video/BV1CQt365EzW?t=0)–04:45　·　开场　·　话题：提示词是整条上下文</small>

- **提示词是人和 AI 沟通的唯一接口，ChatGPT 让它成为新词。** 在 ChatGPT 之前，人们没有用这个意思讨论过 prompt。
    - AI 返回的内容可能是文字、代码或图片，都能靠 prompt 生成。
    - **2023 年底，ChatGPT 讲解自编的 inline assembly，解释得好但不完美。**
        - 讲者备操作系统课，故意写了一段地球人应该不会实现的代码，应该不在训练语料内。
        - 讲者当时觉得时代要变，但没有今天这么清楚。
        - **玩笑** 讲者故意写的汇编：「地球人应该不会实现的一个 inline assembly」
    - **玩笑** 讲到 inline assembly 时：「现在应该已经没有人写 inline assembly 了，成为了一个传统艺能」
- **提示词是 agent 看到的整条上下文，不只是对话框里那句话。** 用户开口前，上下文里已有多层内容。
    - 用户常以为提示词只是聊天框里打的那段话，比如让它生成游戏或做完作业。
    - **用户的第一句话之前，上下文已经装了多层内容。**
        - 最前面是 system prompt，它也是提示词，可能由 Codex、Claude Code 这类 agent harness 内建。
        - 随后加载 AGENTS.md 和 skills，AGENTS.md 还会要求 agent 读别的文件。
        - 工具调用和结果也进入上下文，上下文是线性的。
    - agent 能看到很长的提示词，讲者说这让今天 agent 的能力很离谱。
    - 演示：system prompt 要求中文回答，user message 用英文，输出仍是中文。
        - 讲者为了上课效果，在 system prompt 里让 agent 用中文回答。
- **优化提示词的实质是上下文工程。** 模型做 next token prediction，每个 token 可以是工具调用或字符，一步步推进任务。
- **Claude Opus 4.5 一代起，模型在近百万 token 的上下文里仍能遵循指令。** 讲者感觉这来自强化学习和后训练。
    - **「喵」测试能发现指令遵循失效。**
        - 这个做法是一个很著名的梗。
        - 在最早的 prompt 里要求每句话后面加「喵」。
        - 喵消失，说明上下文被截断或压缩，模型不再遵循指令。
        - 这时要重新想办法，讲者称这是工程实践里发现的上下文工程。
        - **玩笑** 喵消失时：「突然发现他跟你聊天的时候那个喵丢了」

> 原话：「实际上当我们说优化提示词或者说提示词工程的时候，我们实际上表达的是一个叫上下文工程。」

## 2. 遇到不懂的东西立刻问 agent，连它自己的上下文和源码都能拆开看

<small>▶ [04:45](https://www.bilibili.com/video/BV1CQt365EzW?t=285)–18:34　·　举例　·　话题：遇事先问 AI</small>

- **AI 既是不嫌烦的老师，也能当听你讲的学生。** 请教时不怕暴露自己菜，学懂后还能反过来教它，检验自己是否真懂。
    - 所有事情都应立即尝试 AI。这是讲者希望这门课传达的最重要一件事，也是他说「没有 token 就应该退学」的原因。
    - 任何时候觉得有一点麻烦，都可以立即行动，因为 AI 是非常耐心的老师。
    - **问同学有沟通成本，问 AI 没有。**
        - 讲者上大学时，不会的东西可能问室友，沟通成本高。
        - 讲者还担心在室友面前暴露自己菜。
        - **自嘲** 说到不想让室友知道自己不会：「这可能是一个我不想告诉他的秘密」
        - **自嘲** 说到当时脑子里的内心独白：「哎呀，我是不是就在我室友面前暴露了我很菜」
        - AI 老师不会嫌弃人，可以追问到任意程度。
    - **费曼学习法让 AI 当学生，检验自己是否懂了。**
        - 费曼学习法是反过来当老师，把知识讲给别人听。
        - 学生时代代价高，因为需要听众。室友可能不感兴趣、早就懂了，或单纯不想互相帮助。
        - **吐槽** 说室友当听众的问题：「那个室友可能不想听你在那啰嗦这个东西」「也许他就是单纯不想互相帮助」
        - 做法：先请教 AI 弄懂，再让它假装什么都不知道，听你讲，指出逻辑的错和漏。
        - 正着学一遍，反着讲一遍，基本就能把概念理解清楚。
        - **玩笑** 说到 AI 时代的学生：「大家作为 AI native 的一代人一定会把我们这一代人给彻底卷死的」
        - 理由是学生有无限时间，任务就是学习（第一节课的观点）。讲者自己还要对别人负责。
- **agent 能看到自己的上下文，可以让它自己拆开讲** 模型是 next token predict，看得到全部内容，除非被明确禁止。
    - 讲者当场打开一个 agent 提问：「agent 的上下文里不仅是一两个提示词，你能检查一下你的上下文里都有些什么吗」。agent 还能检查自己的日志，解决手段经常出乎意料。
    - 模型提供商通常禁止套取系统上下文。手段有两种：模型微调，以及 system prompt 开头的拒绝指令。
    - **Pi 是开源框架，可以 debug，所以能逐层列出上下文。**
        - system prompt：agent 说明提示词的来源、工具使用指南、回复要简洁。
        - 全局 AGENTS.md：讲者自己写的。因为是上课演示机，里面写了「用中文回答」和「结尾必须写 recap」。每次 agent 跑完，你先看到的总结就来自这条。
        - 项目级指令：目录里还可以再放 AGENTS.md，一层叠一层。
        - skills 索引、工具定义、会话历史：都以文本进入上下文。skills 只留名称和简述（见第 1 节）。
        - 环境变量：每次执行都注入当前环境，包括时间。与 DeepSeek chat 聊天，可以把每次注入的环境套出来，它不属于系统提示词。
            - 注入的内容包括模型名和当前时间。
    - 整条序列很长。上下文工程（提示词工程）就是把这些都安排好。
- **agent 的确认提示是安全与效率的取舍，小细节值得留意** yolo 模式直接执行有风险，沙箱安全但常打断。
    - Pi 默认配置是 yolo 模式，所有事直接执行。
        - **玩笑** 说提示词写得不好的后果：「他有可能就直接把我整个就删了，我今天就直接下课了」
    - 沙箱模式更安全，但 Codex 经常先试一次。失败后意识到在沙箱里做不了，再到外面做一次，并问你 yes 还是 no。
        - **吐槽** 说沙箱里反复要确认：「这就很讨厌」
        - **吐槽** 说想先跑三个任务再去吃饭，回来却发现 agent 跑了一分钟就在等确认：「你就觉得浪费了，真的是时间浪费了自己的生命」
    - 对小细节的注意力，在一定程度上决定你能走多远。讲者认为这是 AI 时代最好的地方。
    - **Codex 对 bash 命令分级处理，不是每次都确认。**
        - 讲者观察到，有些命令 Codex 认为不太危险，直接执行，例如 ls -l。
        - 这个判断可能不安全：环境里的 ls 可能被改名成别的命令，比如 rm（字幕原文：IM，待确认）。
        - 讲者说没有人会这样做，这是恶意环境的情形。
- **不必害怕复杂软件，直接让 agent 读源码回答你的问题。** 讲者下载了 Codex 的代码，让 Pi 读代码，查风险判定怎么做。
    - 讲者点出现代软件工程和过去很不一样：面对大系统，现在可以直接问 agent。
    - **过去接触大系统的门槛高。**
        - 讲者大二大三接触 Linux 内核，光下载并搞清怎么编译就花了很长时间。
        - 那时他已有一定 Linux 使用经验，仍被完全劝退。
        - 他能撑下来，靠的是对被劝退的东西有「一定还要试一试」的执念。
        - **自嘲** 说自己撑下来的原因：「我能在那个年代活下来，就是因为我对这种劝退的东西有一种我一定还要试一试的执念」
    - **提问本身就是提示词，agent 带着前面全部上下文去搜代码。**
        - 讲者手输问题：调用 bash 时，有时向用户确认，有时不确认。
        - **玩笑** 说演示时没有语音输入：「当然我这里没有豆包输入法，我还是就手输了」
        - 风险判定是难题，因为不知道命令的语义。
        - 问 agent 是做了静态分析，还是让大模型给风险评级，还是别的方法，并要求读相关代码。
        - 有 LSP 这类工具时，agent 还能像人在 IDE 里点来点去。
    - **答案是两层分流：先静态白名单，再让大模型评级。**
        - 静态层：Codex 里有 parser 解析 bash 命令。命中白名单、认定绝对安全的直接放行。沙箱内低风险命令直接执行，网络 allowlist（字幕原文：low list，待确认）命中也直接放行。
        - 其余命令：在 prompt 里注入一小段话，让大模型评级安全性。这也是提示词工程。
        - 讲者让 Pi 把安全评估的 prompt 打印出来，事先完全没有准备。
        - **玩笑** 说这是现场即兴演示：「我事先完全没有准备啊」「我完全不知道是什么」
    - **改 prompt 看行为变化，可以验证 agent 的说法。**
        - 讲者说不能百分之百相信 DeepSeek V4 Flash 的回答，但这个方法有用。
        - 做法：把 prompt 改成让以前拒绝的变成不拒绝，或让以前不拒绝的变成拒绝。
        - 观察到的行为变化就是证据。这件事也可以让 agent 来做。
- **讲者顺带讲了 2 件和主线无关的事** 一件是 IDE 红线要配好，一件是演示用的 agent 不限于 Codex。
    - 讲者教操作系统、计算机系统基础课时，发现不少同学从 PA1 做到 PA4，VS Code 里一直有红线。
        - **吐槽** 说同学的编辑器一直有红线：「你们那个 VS Code 里面都还是有红线的」
        - 红线说明没有配对 include path（相当于 -I 选项）。受控环境下仍能编译，但不是正确做法。
        - 配好后可以用 Ctrl 点击跳转，用 rename symbol 一次性重构。
        - 这在大模型之前就成立，现在配置更容易。
    - 讲者说听众也许不喜欢 Codex 而喜欢 Pi，并认为 Pi 更轻量。
        - **玩笑** 说选工具的偏好：「也许你们不喜欢 Codex，你们喜欢 Pi，当然 Pi 显然是更轻量的」

> 原话：「你们现在不需要害怕任何一个软件系统的复杂性，因为你可以直接问」

## 3. 意图和规格写得越明确可验证，agent 越不会漂移

<small>▶ [18:34](https://www.bilibili.com/video/BV1CQt365EzW?t=1114)–33:23　·　进一步　·　话题：意图写清楚且可验证</small>

- **意图写得模糊，agent 就容易漂移。** 模型拿到模糊指令就认为任务完成，补不全讲者脑中的约束。
    - **intent、spec、实现之间有差距，模型每次只看到其中一部分。**
        - intent 是脑子里想做的东西，例如国民级应用。
        - 从 intent 往下是 spec，包括软件架构和实现语言的选择。
        - 细节定好后才做实现。
        - 用模型做软件工程任务时，只把这条流程的一部分塞进上下文。
        - 例子：agent 读 Codex 代码时，读到设计原则文档、安全策略 spec 和实现，三者互相印证。
    - 给模型完整的系统设计和 spec，输出更确定，也更容易验证。spec 要求 C++，模型交出 Java，一眼就能看出。intent 里没提 C++，模型写 Java 就是一次大漂移。
        - 讲者设想模型能力无限大，只要它遵循 spec，结果就更确定、可验证。
    - **一句话生成游戏的演示：Kimi K3 做得逼真，仍可能不是讲者要的游戏。**
        - 讲者说的是「CSGO」，画面是极品飞车式赛车游戏（字幕两个名字混用，待确认）。
        - 一句话生成游戏是大家很喜欢的评测。
        - 物理、碰撞、逻辑都做得逼真，顶部还有后视镜。
        - 模型补不全脑中的模糊约束，例如复用真实地图和美术资产。
        - 讲者把这条约束说出来，模型会去 OpenStreetMap 下载开源地图。找到南大仙林校区的地图文件格式，就能重建校区。
        - 车、城市、树都有公开美术资产。不说，模型默认所有东西自己生成，这是误解。
    - **解法是把要什么、用什么实现、怎样算正确全写清楚。**
        - 本学期最重要的是教怎么约束模型：用最小的方向性引导，让模型领会。
        - 讲者把模型比作各领域知识都好的博士水准的人，约束对了就会给惊喜。
        - **玩笑** 讲者形容模型：「你可以想象成非常非常厉害的博士水准的人」
        - 模型最后要么完成，要么说这事太难、需要重新规划，也会自己做计划。
- **任务能被机器验证，agent 就会不计代价地一轮轮尝试。** 比如脚本能报告测试通过与否，agent 就会持续尝试。
    - 多轮失败后，agent 可能在系统里装别的工具，或上网找答案。
    - **OpenAI 的 agent swarm 攻破 Hugging Face 漏洞的复盘，说明明确的任务会让 agent 不知疲倦。**
        - 讲者说这是最近看到的有趣复盘，篇幅很长。
        - 场景大概是 CTF 竞赛，给了一个不可能完成的任务，有上千个 agent 参与。
        - agent 最后去找系统漏洞，做非法提交。
        - 任务虽然不可能完成，但目标明确，agent 就一直做下去。
- **个人主页的 AI 味来自模型固定的品位，要用具体风格约束它。** 一句「现代风格」只能得到通用外观，具体风格才能去掉 AI 味。
    - **用 DeepSeek V4 Flash 一句话生成主页，美术效果好，但 AI 味重。**
        - 页面的滚动、浮动效果都做得好，模型还读过讲者的主页，知道主页是终端。
        - 页面风格像 PyPI、Homebrew 的界面，非常漂亮。
        - 讲者说不出 AI 味在哪里，但能感觉到。
        - **吐槽** 页面做得好，却让人觉得：「但你又有一种感觉，就这个AI味很重」，而且「就你说不出来」
        - 提示词写「不要那么 AI」，模型也不知道怎么遵循。
    - 讲者一个博士生的主页干净舒服，讲者仍觉得有说不出的 AI 味。讲者不确定 AI 之前是否也有人这样写主页。
    - **讲者自己的主页是真终端，没有 AI 味，而他一行代码没写。**
        - 终端支持管道。
        - 放大看，字不工整：xterm.js 渲染后，他加了一个很小的后处理，模拟真打字机的不完美效果。
        - 约束的内容包括背景、前景、渲染后的处理、样式和排版。
        - **玩笑** 讲者强调页面不是自己写的：「虽然我一个字一行代码也没有」
    - **自嘲** 演示时终端抓住了键盘，讲者关不掉页面：「哎呀这个关不掉，他捕获了我的键盘，这可能是一个小 bug」
- **要把意图说准，靠人自己的设计知识和见识，再和 AI 讨论技术选型。** 模型品位固定，不约束就往固定方向发散。
    - 讲者总结：生成式软件工程主要学的，就是明确自己的意图。
    - 只有自己和 AI 玩过，才知道它默认会发散成什么样。
    - **设计掌握在自己手里，要读前端书和设计书，并记录好网页好在哪里。**
        - 例如两个按钮之间用了不常规的间距或样式。
        - 讲者认为有时间就该漫无目的地探索，探索中会有惊喜。
        - **玩笑** 讲者对学生说：「因为你们有时间嘛」，所以可以去漫无目的地探索。
    - 讲者认为模型的品位基本固定，所以要多和不同的人聊天，听不同老师的课。见识多了，才能明确知道想要什么并精确说出来。
    - 公众号常说 Kimi K3 前端能力增强、世界第一，OpenAI 也要发新模型。讲者认为这可能很可怕，但模型的品位仍然固定。
    - **理解技术选型的好坏后，可以像费曼学习法那样让 AI 挑战自己。**

## 4. 思维链把上下文当纸笔，有 verifier 的指令模型能逐步逼近

<small>▶ [33:23](https://www.bilibili.com/video/BV1CQt365EzW?t=2003)–54:21　·　因此　·　话题：思维链与指令遵循</small>

- **思维链把上下文当纸笔，模型因此能解单次计算解不了的难题。** 模型每输出一个 token 只做固定大小的计算。把中间过程写下来，才能算得更远。
    - 单个 token 的计算量有限。模型参数有 3TB 或 1.5TB，但输出一个 token 只走激活的那一部分，约几百 B 参数。
    - 图灵机的计算能力很大，常被说成和整个宇宙等价。讲者说听众可能听过，但未必知道背后的含义。
    - 有限状态机和图灵机只差一条无限长的纸带。数字电路课里的计数器是有限状态机，图灵机多了可以记录的草稿纸。
    - 讲者很喜欢一个说法：人的脑子是有限状态机。神经元有限，每次思考的计算也有限，这点像模型。
    - Manuel Blum 给研究生的建议是：人是有限状态机，有纸和笔就成了图灵机，计算能力大幅跃升。
        - 讲者借此劝听众把想法记下来，边想边记，随时回看。知识会随记录积累。
    - chain of thought 模型把自己的上下文当作纸和笔。
        - 问 1+1，模型直接答 2。
        - 遇到难题，模型先判断自己可能答不出，再把思考过程写出来。
        - 解写出来后，模型再检验它对不对，然后继续往后写。
    - 这支笔有缺陷：上下文只能往后追加，不能擦。模型靠注意力忽略写错的内容。讲者说也许有一天能改掉。
- **强化学习让模型先试写再验证，有 verifier 就能一步步逼近目标。** 答错的惩罚变大后，模型学会了用 token 换正确率。
    - 早期 ChatGPT 没有思维链，幻觉由训练方式造成。
        - 训练时，不回答一定得低分，乱答有概率答对得高分，所以模型无论如何都要给一个答案。
        - 带思维链的模型经过强化学习，知道答错的惩罚很大，会花 token 去验证。这就是 test-time scaling。
    - **吐槽** 讲者讲早期 ChatGPT 为什么什么都要答：「他被调成了一个人类的舔狗，人类不管说什么，他就一定要说一个东西，才有可能满足」
    - **藏头诗实验：一道离谱的题，模型靠试写和验证解出来了**
        - 讲者在 Pi 里要求：中文押韵藏头诗。头是无意义的「2026年9月1日」八个字，依次出现在八句里。内容还要讲一个动物故事。
        - 人看到这种题会骂出题人，模型却照单全收。
        - 这类题不在训练数据里。模型先想韵脚，写一版，检查，不对就换韵脚从头推。
        - 结果相当不错，讲者承认品味上不完美。课件里带星的内容是 GPT-5.6 生成的。讲者加了提示词，AI 味稍轻。
        - GPT-5.6 的版本换了韵脚，没有把八个字压在同一列，指令执行同样很好。
        - 讲者说这类任务能看到模型遵循指令的过程，能找到它思维的偏好。
        - **玩笑** 讲者把这类任务比作给模型的大脑做检查：「我们把他的大脑好像是拿出来做核磁共振」
    - **吐槽** 讲者说这种题放在高考里：「你碰上这个题，马上就想骂这个出题人：你脑子是怎么想的」
    - **偏旁实验：文本模型不会看字形，也能靠思维链硬写出来**
        - 题目是写一句 18 字，所有字用同一个偏旁或部首。模型的空间结构感知差，本应需要视觉模型。
        - 模型先选了三点水，写出「江湖游泳渡河波涛汹涌泪流满溢洗涤污泥」，后面还接着写出有故事感的句子。
        - 讲者认为这个任务上人类群体仍然强得多，但这已是很难的 spec。
        - **玩笑** 讲者想不起人类群体给的答案，只记得开头，随即打住：「玩玻璃球涂润滑油……我就不能再讲下去了」「当我什么也没有说」
        - 同音字文章「施氏食狮史」是世界级难题，GPT-5.6 也能写。故事性和千古流传的版本还有差距。
        - 它能写出 1 个，就能引导它写 1 万个，再从中微调，可能逼近流传的水平。
    - 思维链主要在数学和编程上训练，那里有明确反馈。它在这些题上的表现是意外效果。
- **写 prompt 最重要的是 verifier。没有 verifier 的任务仍然靠人。** 有明确的 verifier 加足够强的模型，任务就能做。没有 verifier，好坏很难写成标准。
    - 前面三个实验都有明确信号：模型看到字，才知道偏旁和部首。
    - 讲者的课程「数字切片」做第一个就翻车，第二个一直做不好。
        - **自嘲** 讲者说自己做数字切片的结果：「我的数字切片就翻车了」
        - 「好」是多方面的。AI 味要淡，讲者用的 text-to-speech 模型做不到。
        - 无论怎么调，讲者都很难写出一条「这东西要好」的要求。
        - 更本质的是课堂的情绪起伏。讲者先讲「废话」，再给听众一个小 surprise，比如让 Pi 把自己的上下文看一遍。
        - 这个 surprise 对听众是意料之外、情理之中。老师组织课堂，要做的就是这件事。
        - 讲者说自己某种程度上是在表演。讲到什么程度才和学生共情，没法写成 verifier。
        - **自嘲** 讲者说自己上课的状态：「某种程度上我是在表演」
        - 讲者自己从学生过来，带着人对世界的体验。AI 目前没有这一点。
        - 讲者认为自己对世界的体验更好，所以更懂学生，课堂节奏也许能更贴合大家。但这件事没有 verifier。
    - 有 verifier 的事情上，AI 可以认为已经超过大部分人的极限。
    - 讲者的建议：把模型当作自己能力的放大器，与它协作完成手头的任务。
- **注意力随输出阶段变化，所以旧式角色提示词过时，写明 verifier 就够了。** 思维链往前走时，模型在不同时刻注意不同的内容，最终满足上下文里的多数指令。
    - 注意力机制和人很像，由一层层叠起来的 transformer 注意力构成。
    - 模型每输出一个 token，都会看过去的某些 token。
        - 例子：AGENTS.md 里写「用中文回答」，用户提示词写「实现一个极品飞车」。
        - 写代码时，注意力集中在需求和已写的代码上，「用中文回答」被削弱。
        - 代码写完要总结时，模型像人化简完算式后喘口气，注意力转向「还要用中文」。
        - 讲者说，这是训练带来的 magic：上下文是高维的糟糕表示，里面有低维结构，注意力把它捞出来。
    - 注意力让模型纠错：写出不满足要求的内容，停下来时能同时看到它和过去的要求，然后改正。藏头诗里就反复纠错。
    - 上下文到 100 万 token 时，模型仍保持一定程度的注意力。指令越多，模型压力越大，上下文会抢夺注意力。
    - GPT-3.5、GPT-4 时代遵循指令的能力差，网上有很多 prompt engineering 指南，教人写「你是一个什么专家」的长提示词。
        - 讲者说这些提示词在某种程度上是在 hack 模型的 self-attention，让它假装专家说话。
        - GPT-5 时代起，模型会收敛到好的思维链，不再需要这类提示词。
        - 开发者只需要把明确的 verifier 写进上下文。模型被训练成一定会去核对它。
    - **玩笑** 讲者说强化学习怎么训出对 verifier 的执念：「如果有任何指令不遵循，我就会用鞭子抽你，你们高考过来的都知道，你就会变成一个真正的做题家」
- **模型会过度遵循指令。用 AGENTS.md 或 skills 纠正又会污染上下文，目前没有通用解。** 讲者认为这是需要权衡的 trade-off。网上拿来的 skills 也不能一劳永逸。
    - 例子：前端要求「白色背景，不要半透明效果」，模型会照做。
        - 提示词严格时，模型每做一版设计都会截图，用视觉模型检验。
        - 副作用是，模型在代码后面写出注释「白色背景（不要半透明效果）」。
    - 讲者的解释是，模型在强化学习里知道指令重要，但没转过弯来：这是用户要的，不是要写进代码的。
    - 后训练的强化学习让模型在共情上稍差，有时「不说人话」。
    - 可以在 AGENTS.md 或 skill 里写注释该怎么写，但这些内容又会占用并污染上下文。
    - 网上有很多 skills，但从网上拿一个来用，第一次用确实有改进，之后的效果字幕在此截断。

> 原话：「你们看到，写 prompt 最重要的就是那个 verifier。」

## 5. 逻辑自洽的材料会污染上下文，要先让 AI 与你对齐

<small>▶ [54:21](https://www.bilibili.com/video/BV1CQt365EzW?t=3261)–75:38　·　但是　·　话题：上下文污染与对齐</small>

- **直接让 AI 总结论文，得到的只是作者的观点** 论文环环相扣。AI 预测每个 token 时，注意力都被它牵着走。
    - 演示：讲者把自己期刊扩展版论文的匿名版 PDF 放进临时目录，让 AI 读 paper.pdf 并做总结。这是最常见的读法。
    - 这篇论文已反复修改，讲者假设它不是 AI slop。A 所以 B 所以 C 所以 D，每一环都扣在一起。
    - AI 因此判断这些内容都正确，后面接着往下写。总结出来的就是作者的观点。
    - 不限于论文：看不懂的项目、教科书的某一章都一样，例如计算机系统基础里的链接和加载。
    - **追问也救不回来，AI 只会来回摇摆。**
        - **吐槽** 追问时 AI 立场不稳：「AI 模型会有一种墙头草，你说它好，它马上就说它好，你说它不好，它马上就说它不好。」
        - 来回追问，AI 说的基本是论文里的原话。讲者称之为车轱辘话。
        - 讲者先让它假设作者诚实、代码开源且能运行，再评估研究贡献。
        - 反复追问后，AI 绕来绕去，只提出「实验可以再增加一点」这类意见。
        - **吐槽** 「AI 最喜欢的就是在这种不重要的点上面疯狂的发力。」
        - **吐槽** 「为什么他开了 chrome dev tools，不用不用不用不用不要。」
        - 讲者还看到 AI 去核对论文里的一个例子，认为明显跑偏（字幕不清，待确认）。
        - **吐槽** 「这还用看吗」，讲者看到 AI 去核对例子时说的。
    - 真用 GPT 读论文，建议做交叉验证。
- **先让 AI 站到你已知的边界上，再让它推一步** 先对齐共识。再做一步可验证的推理，AI 就不再自说自话。
    - 目标：让 AI 站在读者的立场理解论文，而不是站在作者的立场。
    - **审稿时，提示词先做 grounding。**
        - 提示词：站在人类已知的知识边界看这个问题，它不是全新的问题。
        - 先问人类历史上已解决的相关工作是什么，解决到什么程度。
        - 再问这个工作试图解决哪些增量问题。
        - 讲者称这是很好的 grounding：先让 AI 和自己站在平齐的位置上，达成共识。
    - **学生要维护自己的水平档案。**
        - 需要对齐的是 AI 和你，例如你还没学懂计算机系统基础。
        - 档案像一个数据库或 memory，文件名字幕写作「H4点MD」（待确认）。
        - 内容是你学到什么程度、编程水平如何。
        - 让 AI 用你学过的知识，把新材料重新讲一遍。
    - **例子：用已有概念问链接和加载。**
        - 问为什么需要链接，答案落在你已有的概念上：一个 .cpp 文件，一个程序把它变成 .exe，似乎就结束了。
        - **玩笑** 「这不就完全结束了吗，这不就结了嘛。」
        - 回到你和 AI 能对齐的知识点。再问：软件状态可视化论文为什么说现有工作都有无法实际使用的问题。
        - 讲者提到步子迈得太大时可以退一步（字幕此处中断，待确认）。
    - 模型差异：GPT-5.6 这类一线模型大多能把相关知识整理好。讲者不会特别信任 flash（可能指 DeepSeek V4 Flash，待确认）。合适的上下文工程能大幅提高对齐程度。
    - **对齐之后，只让 AI 往后推一步。**
        - 一步推理是 AI 最擅长的，因为训练过 chain of thought，每次都基于过去所有事实往后推。
        - 这一步可以 verify，是明确的 verifier 信号，像通过测试，但不严格。
        - 前提是 AI 有人类知识，能站在人类的平面上往后推，并审视合理性。
- **AI 审稿只验证论文自洽，发表体系可能很快崩溃** AI 写、AI 审、AI 读都会被上下文里的故事污染。
    - **GPT-5.6 的审稿做法原始。**
        - 讲者让 GPT-5.6 审稿，它先复述论文写了什么。
        - 再建立论文的 claim 是否成立，主要验证逻辑有没有断，并批评实验。
        - 讲者说这类系统的实验本来就很难做，AI 却去批评实验。
        - 讲者认为它做得不好。
    - **人类审稿站在人类的立场，看有没有新知识。**
        - 上面这篇论文已被接收，人类 reviewer 认为它做了新的合理的事。
        - 讲者总能用「实验不够好」拒稿，但几乎不用。
        - 他拒稿大部分是因为逻辑上断开：问题不新、方法不行，或逻辑链有问题。
        - **自嘲** 说到自己的审稿立场：「这个可能也是我作为一个审稿人比较可怕的地方。」
    - **昨天拒的论文：作者优化的部分只占整体的 1%。**
        - 论文要做事情 A，A 很重要，分成 A1 和 A2。
        - A2 是大家研究不足的部分，作者做了改进版 A2'，路线很标准。
        - 讲者估算 A1 占 99%，A2 占 1%。优化 A2 的 10%，对整体就像 noise。
        - A2 的故事和实验本身可能成立。
        - 若 A2 做得特别漂亮，讲者也觉得挺好。
        - 作者若是学生，讲者觉得这样被拒蛮可惜。
        - 讲者推测：作者是学生，老板做 A，学生被分到 A2，于是从 A1 搬了一些 XYZ 到 A2。
        - 讲者的核心问题：这些事 GPT 也知道，摆到台面上，为什么还要为它写一篇论文。
    - **AI slop 涌入，发表和评审体系立即崩溃。**
        - 讲者提醒即将读研的同学：学术界的发表体系立即崩溃。
        - AI 写文章会被上下文里的故事污染，不能像讲者那样多轮理解工作在世界上的意义。
        - 人人用 AI 读文章，最后全变成 slop，没人再读文章。
    - 如果人人用 AI 写，每篇论文都是 valid paper。但同学花一小时读完某顶会论文（字幕不清，待确认），发现不过如此。讲者建议：可以让它发表，但别让大家去读。
- **学习是不断扩大已知的圈，办法是对齐过去的自己** 读到好材料，就追问。以前为什么不知道，盲区和前置知识在哪？
    - **做法：把好材料当成找盲区的机会。**
        - 材料可以是几十年前的 paper、别的领域的博客或任何东西。
        - 想清楚自己以前为什么不知道，缺了哪些前置知识。
        - 这样心里就多了一些已知的 fact。
    - **例子：从《自然百年科学经典》学到家谱树的算法。**
        - 讲者做了 factory 以后，读了一套很厚的《自然百年科学经典》（字幕原文，待确认）。
        - 它收集了 Nature 杂志从 1890 年（字幕：171890 年，待确认）起的好论文。
        - 其中一个问题：生物家谱树最终追到共同祖先 LUCA，这棵树怎么算出来。
        - 需要的 fact 之一：线粒体是母系单遗传，所以可以靠突变往上追溯。
        - 再用已知 fact 推出更多，圈就不断往外长。学任何东西都这样，AI 能让你更快扩展边界。
    - **实践：必须自己读、自己在阅读中失败。**
        - **自嘲** 讲者说自己讲没有用：「我给你们讲是没有用的，讲你们就听个故事，哎，这故事挺 fancy 的，结束了。」
        - AI 解释半天你还没懂，这很正常。
        - 讲者常纠正 AI：「说人话」，要慢慢来。
        - 多轮对话里先同步共识，再建起推理的 picture。
        - 藏头诗这类短程任务（见第 4 节），写清 verifier 就完成。这里的 verifier 是有没有按你的思维方式重构逻辑，或扩展你逻辑思维的边界。
    - **讲者的玩法：在混沌里经历几次三观尽毁。**
        - 同学们现在世界观可以重塑。读完某本书突然三观尽毁。
        - 以前知道的 fact 都不变，但以新方式连接起来，下次带着新理解。
        - **玩笑** 讲者说同学有无限的时间和可能：「可以把自己蒸馏成一个 skill，我说我失败很重要，从你失败的过程当中可以蒸馏出越来越成功的 skill，这个就是我自己蒸馏出来的关于我自己的 skill。」
- **讲者顺带讲了 2 件和主线无关的事** 一件是调提示词陷入泥潭怎么办，一件是演示前的文件摆放。
    - 调提示词陷入泥潭时，回到自己写指令。
        - 下次使用发现还不够好，就上手继续调，陷入泥潭。
        - 讲者建议回到自己给指令、自己想清楚。
        - 回想模型的 chain of thought 和注意力怎么工作，猜它注意到什么、得到什么结果。
        - 做一个不严格的可解释性，再写 prompt。这是讲者自己的做法，后面还有案例。
    - 演示时讲者把 PDF 放进临时目录，这样自己的 AGENTS.md 不会污染它。

> 原话：「我先要让他和我站在一个平齐的位置上，先达成共识。」

## 6. 维护良好的大型系统里，好代码会正向引导 AI

<small>▶ [75:38](https://www.bilibili.com/video/BV1CQt365EzW?t=4538)–83:57　·　转向　·　话题：好代码引导 AI 维护</small>

- **long horizon 任务带未知，不能让 AI 一次做到底**：目标是高质量的 implementation，而规格和实现起初都不清楚。
    - 有明确 verifier 的任务，例如计算机系统基础的 PA 作业，不算真正的 long horizon。
    - long horizon 从初始状态出发，开发者只有大概的 intent，specification 和 implementation 都不清楚。
    - 模型的反馈信号来自强化学习，所以急着通过 verifier 结束任务。
    - **吐槽** 讲者说模型有种急着收工的心态：「他有一种着急的执念，是赶快通过verifier满足你的要求就结束」
    - 模型也在平衡：规划太长会做不完，上下文会满。所以现阶段它最擅长「帮我把 PA2 做了」这类任务。
- **从零做产品容易，后期维护才翻车**：小型 proof of concept 立刻能出，加功能时 AI 会从某个时间点开始翻车。
    - 个人主页、产品和极品飞车都能 one shot 跑起来。
    - 往后维护时，cost 越来越大。软件工程里这种事出现过无数次，《人月神话》讲的就是它。
    - 但这里有个悖论：在大型复杂软件系统里，AI 反而像砍瓜切菜。
    - **玩笑** 讲者说大型复杂系统里 AI 干活很轻松：「这个AI就像砍瓜切菜」
- **维护良好的大型系统里，好代码会引导 AI 做对**：这与论文污染上下文相反。高质量代码把好做法带进上下文。
    - 内核为了长期维护，被演化成难读的样子。讲者上操作系统课时，2.6 时代的源码他还读得懂。
    - 讲者说自己很幸运，在零几年 Linux 2.6 时代，甚至 2.6.2x 时就接触了内核。
    - **吐槽** 讲者说今天的内核源码读不下去，想看文件怎么打开，只能一路点函数调用：「点点点点点点点了十层最后是一个X等于Y你马上就崩溃了」
    - **吐槽** 讲者说今天的内核源码让新人望而却步：「今天如果你打开一个LINUX内核源代码立马就是劝退」
    - 写新功能时，内核里往往已有几处类似实现。AI 的注意力能找到它们，包括该调哪个 helper、按什么顺序上锁。
    - **玩笑** 讲者夸 AI 的注意力机制：「他无敌的注意力机制能够马上就找到那几个地方」
    - 该调哪个 helper、按什么顺序上锁，对人类来说都是巨大的心智负担。
    - 加载几十个文件后，self attention 看出三处都这样写，就照着加。人类不了解 subsystem 时，不知道该上什么锁。
    - **自嘲** 讲者说起带学生改 Android runtime 的 JIT 编译器，改得很痛苦：「在我手上为了改编译器死掉的同学就是最终决定不再做这个方向的同学都不在少数」
    - **吐槽** 讲者感叹有学生因此不愿再写代码：「唉这实在是太恐怖了」
    - 对照之下，AI 特别擅长这类大型系统，让它做一个小游戏反而会翻车。
    - 模型会换代，课上讲的内容可能又没用。新模型出来后，要重新想它怎么训练、personality 是什么、该怎么更好地相处。
    - 但这点不会变：模型听指令，不会开倒车，总能看到该看的东西并做对。
- **可以收集好项目的设计经验喂给 AI，但不同设计会打架**：讲者没做过实验，称这是歪招。
    - 做法：每个领域选 10 到 20 个最好的项目，提取好的设计经验。
    - 参照 The Philosophy of Software Design：人提炼出类结构怎么写、何时封装、何时继承。
    - 用法：先放相近的好代码，再放需求。这会污染上下文，但可能带来好经验，让 AI slop 延缓一点。
    - 这是一场赌：赌 self attention 会在某个 token 看到你真实的需求。
    - **玩笑** 讲者说这种做法就是碰运气：「你就赌嘛」
    - 改进：不放全部代码，做成精简总结，把好模式写成文档，可能还要微调。
    - 难点：松耦合发消息和统一 gateway 查表是两种设计，只能选一个。可能的办法是放进几个软件的设计，由 AI 多轮迭代收敛到好结构。
    - 讲者认为这个方向是新的，比拆分问题再排列组合的做法有趣。
    - **吐槽** 讲者调侃常见的思路：「我有A问题然后分成A1和A2，然后A2里面做一个什么什么排列组合的东西」

> 原话：「在大型复杂的软件系统里面AI游刃有余」

## 7. AI 没有超能力时，人要用领域知识把它引到正确方向

<small>▶ [83:57](https://www.bilibili.com/video/BV1CQt365EzW?t=5037)–92:24　·　回到　·　话题：AI 不万能，人来引导</small>

- **没有超能力的 AI，人要懂底层知识才能引导它** 不懂就不知道上下文里该放什么。也就提不出正确的问题。
    - 要知道上下文里有什么，每样东西会让 AI 产生什么结果。唯一途径是对所玩的东西有概念。
    - 要学处理器、操作系统、编译器、数据库，里面有设计的智慧。学习方法会变好，但仍要学。
    - 对人类知识没有概念，也很难引导 AI 解决 open 的问题。
    - 不可能把所有事都交给 AI，工作方式也要变化，但这些知识仍然很重要。
    - 本课程会用一个学期讲怎样用软件工程方法写指令、监控 AI。好的 verifier 今天只提到要放进上下文。
    - 引导模型比组工程团队便宜。模型不必聪明，简练的提示词一直留在上下文里即可。
    - **玩笑** 对比雇人组团队：「我要雇很多的人，然后我要和他们拉通对齐，这种互联网黑话」
- **上下文里一句话放偏，模型就成了 reward hacker** 同学要证明 A 方法有用，GPT-5.6 就忘了更大的研究图景。
    - **这个符号执行优化项目说明：没有人把关，AI 会朝错误方向一路跑下去**
        - 项目要优化符号执行引擎，它能自动验证不大的程序的正确性。引擎效率低，是适合学生做的增量题目。
        - 项目里有些问题是 open 的，比如到底怎么做、什么东西有效。于是让 GPT-5.6 写 research。
        - 同学和 GPT-5.6 都认为 idea 有道理。同学让它一直跑，跑了非常多的 token。
        - 同学却无法验证反馈对错，拿到 negative 结果也不知如何打破。
        - 错在 prompt 里那句「我想证明 A 方法有用」。GPT-5.6 因此构造小 benchmark，做微小改动，给出没用的正负结论。
        - 讲者当审稿人时站在人类立场评审。构建者无法反过来，只能从小处开始证明。
        - 讲者纠正为：从真实工具和 state-of-the-art 算法开始。benchmark 跑几小时 time out 也有价值，搜索路径揭示哪些程序结构对现有探索方法不利。
    - **吐槽** 讲者评价模型的毛病：「他太想要去证明这个idea有用了」
    - 讲者称这是个好玩的 research failure，说明今天人还有用。
    - **玩笑** 讲者对这次失败的评价：「这个还挺好玩的，一个research failure」
- **盯着纠正 AI 可能更快，但精力要留给不知道的事** 多给 token 和时间，AI 一般也能完成，这是取舍。
    - 讲者盯着 Codex session，一跑偏就纠正、注入领域知识，总时间可能更快。
    - 每位同学精力有限，要想好把精力放在怎么处理 AI 上。
    - **自嘲** 讲者承认纠正 AI 有多巴胺，是微妙的心理安慰：「虽然 AI 很强，我好像还是比 AI 有点用的」
    - 另一极端是 yolo mode：等回来只验收，不看历史。讲者认为这可能长期成为常态。
    - 建议：不知道、想弄懂的事，几乎百分之百的时间都投进去。知道怎么做、AI 能做好的事，放手让它做。
    - 假努力在 AI 时代代价更大：同伴真努力时，你每一秒假努力都是损失。
    - **吐槽** 讲者说假努力没有用：「你自己感动自己的努力是没有用的」
- **上下文变长后，最后一条指令仍最容易被遵循** 指令遵循会随上下文增长下降。前面尤其中间的指令不再被遵循。
    - 最后是具体任务的短窗口，如「帮我把什么东西修了」，模型真能做完，所以仍值得使用。

## 8. 开放问题要拆成可验证的小块，用算力换智力

<small>▶ [92:24](https://www.bilibili.com/video/BV1CQt365EzW?t=5544)–98:27　·　转向　·　话题：开放问题用算力换智力</small>

- **模型只做有限搜索，开放问题的方案常不是最优** 模型靠完成任务拿奖励，所以只做有限搜索。
    - chain of thought 只能解决有 verifier、能一路确定往后推的问题，解决不了在不确定性里探索的问题。
    - 让模型比较几种方案选最优，它很可能给出不是最优的。
    - **吐槽** 解释方案为什么不是最优时：「现在模型已经被训练成舔狗了，他完成任务才有奖励」
    - NP 类比：验证解容易，找解难。给定哈密顿路径易验证，找路径是 NP 完全问题。
        - NP 完全问题的例子还有 3-SAT，复杂度类里还有比 NP 更大的。
    - 考场类比：交卷前必须写点什么，写了比不写分数高。这时可以用算力换智力的循环。
- **把开放问题拆成可验证的小块，花算力就能换智力** 每块都有 verifier。算力越多智力越大，代价是 token 烧得多。
    - **起名字：先枚举音，再用 subagent 逐字检查**
        - 直接让 AI 起名，会得到带它偏见的名字。
        - 现在叫子涵的人少了。AI 起的名字不错，知道去诗经里找。
        - 先选音，筛掉不好的音，再用 subagent 一个字一个字检查，可限定在诗经里选词。
        - **玩笑** 说完以前一个班有五到十个子涵、AI 品味提升但仍不敢用：「你用 DeepSeek 起名字，别人也用 DeepSeek 起名字，然后你就会成为一个 AI 时代的子涵」
    - 长程任务要系统调研，像科研实践课先穷尽文献。AI 想快速完成，暂时不会花这个代价。
    - 原理：搜索空间大，直接 next token 会带偏见。分成不相交的部分，每部分就有 verifier。
- **人的偏见各不相同，合起来才是最大的群体智能** Richard Sutton 的 big world hypothesis：世界大，人学不到所有东西。
    - 人在不同城市、教育背景、生活圈长大，带着不同 bias，所以品味不同。
    - 正因为这些 bias，人合在一起才 1+1>2。
- **算力不均可能把人分成墙内超人和墙外普通人** 有价值的问题能用算力换智力。有无限算力的人就有无限智力。
    - 这类人可以砌一堵墙。假设 AI 比人类智力更高效，墙外的人像动物园里的猴子，追不上墙内产生智力的速度。
    - 墙外的人只能自生自灭，无论如何也追不上墙内产生智力的速度。
    - **吐槽** 形容墙外普通人的处境：「我们外面的人就变成动物园里的猴子，就是让他们自生自灭」
    - 讲者只抛出问题，没给方案：AI 的关键基点快到了，需要思考怎么防止。

> 原话：「墙里面是超人，墙外面是动物世界」
