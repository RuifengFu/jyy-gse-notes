## 怎么读

每讲约 1.8 万字，PDF 约 25 页。笔记按金字塔结构写：外层概括内层，读到哪一层停下都不会漏掉核心论点。

- **一句话** + **结构图**：开头一张图就是目录。每个方框是一个小节，写着标题、时间段和这节的核心论点；箭头上写小节之间的关系（因此 / 但是 / 举例 / 转向 ……）。
- **目录表**：每节一行，写这节的结论；时间可以点击，直接跳到 B 站视频的那个位置。
- **小节**：按话题分（5–9 节），不按时长分。小节标题就是这节的结论。下面是 2–5 个分论点：粗体是结论，后面一句是讲者的主要理由；再往下是支撑它的理由、例子、数字和演示结果，一个故事写成一条，经过放在下一层。
  - 只想快速看：读小节标题和第 1 层（每节约 5 行）。想看依据：再读第 2 层。想看细节：读到底。
  - 一个话题只在一个小节里展开，别处只写「（见第 N 节）」。
- **玩笑**、**吐槽**、**自嘲**：讲者的玩笑原话，放在它出现的位置，用「」引讲者原话。
- **提到的资料**：讲者提到的文章、项目、工具、推文，附一句「是什么、为什么提」。
- 文字按[简明技术中文](https://github.com/mzopedia/simplified-technical-chinese)（仿 ASD-STE100 的受控中文）的规则写：一句一事，一词一义，不用无数值的程度词。
- **术语表**：本课的术语和字幕的错误识别。标「（拼写待确认）」的是按读音猜的名字。

## 怎么做的

B 站 AI 中文字幕（只用字幕，不用视频和音频）→ 大模型（2026-11-08 起用 Claude Sonnet，之前是 DeepSeek）通读全文，按话题切成小节并统一术语 → 每节只读自己那段字幕，按简明技术中文写全这段的实质内容，讲者的玩笑用「」引原话 → 按金字塔结构组织（结论在外层，依据在内层）→ 对照字幕补漏一轮，并单独查一遍漏掉的讲者原话 → 检查脚本查出的长句和禁用词再改一轮 → 画结构图 → pandoc + Chrome 导出 PDF。

### 和旧格式的对比

01–08 最早用的是旧格式：按时间每 3.5 分钟切一段，逐段总结，再写一条「全课主线」，附画面截图。每讲约 4 万字，比字幕本身（约 3 万字）还长，相邻段落和主线之间有重复。2026-11 起 01–08 全部换成新格式；旧格式在 git 历史里（提交 `bb7ff7c`）。

### 金字塔结构（2026-11-08）

上一版（v3）的小节是平铺的列表：一个「要点」行加 10 条左右并列的条目，每条开头的粗体是话题名（例如「**morning paper**」），不是结论。现在（v4）小节标题和第 1 层都写结论，依据放在内层。

除了上面的覆盖率，还加了一项「只读外层」测试：每份笔记只留标题、一句话、小节标题和第 1 层（v3 留「要点」行和粗体话题名），长度都约 2 千字，再按同样的方法判断核心事实覆盖了多少。第 08 讲用来调方法，第 03 讲之前没有生成过。

全文的覆盖基本不变，每讲多约 1 千字。只读外层时，5 讲里 4 讲能读到更多核心论点，第 02 讲变少。第一次尝试只在第 1 层写粗体结论、不写理由，外层只覆盖 37–42%，比 v3 还差：外层要带上理由，只写结论不够。生成和评测现在都用 Claude，可能偏向自己的写法；抽查了 15 条判断，13 条同意。
